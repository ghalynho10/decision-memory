# 0010. Abstention verification reliability

**Date**: 2026-08-12
**Status**: In Progress

## Summary

The query pipeline verifies atomic sub claims, and it emits whole sentences. Decomposition is a check on a draft sentence, not a rewrite of it. A sentence reaches the answer only when its decomposition is valid (it adds nothing to the parent and omits nothing from it) and every sub claim is supported by the evidence. Otherwise the whole sentence is dropped and contributes nothing. Coverage then judges whole sentences, so a decision that takes several clauses to state can still be answered, while a fabricated clause still takes its whole sentence down with it. Generation is also told, in plain words, which part of the record each evidence chunk is, so a question about what was decided gets an answer that states the decision instead of a description of how the system works. A sub claim that says strictly less than one of its siblings is skipped rather than checked, because a fragment like `The decision was made.` carries no object and no evidence can support it, and letting it fail was dropping correct sentences. The gates that prove an honest abstention now check why the query abstained and not only that it did, and any figure a decision rests on is measured over twelve runs rather than six.

## Requirements

**User stories**:
- As a user of the query command, I want an honest abstention when the evidence does not support a claimed decision, so that I am not shown a cited answer that mixes a fabricated decision with a real borrowed clause.
- As an operator, I want the debug trace to show how each sentence was split and why each piece survived or was dropped, so that a bad split is visible rather than silent.

**Acceptance criteria** (the contract, each IDed and independently checkable):
- **AC-1**: A draft sentence that welds a fabricated decision to a verbatim borrowed clause is decomposed and verified by sub claim. The fabricated sub claim comes back unsupported, and its whole parent sentence is dropped, so the fabrication cannot reach output and neither can the borrowed clause that was carrying it. A decomposition that omits the fabricated clause entirely fails the completeness half of AC-11, so the parent is dropped there too rather than emitted as safe. Deterministic tests cover both attacks: an explicit fabricated sub claim, and an omitted one. **Amended 2026-08-14: the omission attack is re proven under the AC-11 base set matcher, not assumed to survive it.** Both halves of the AC-11 test match through `tokens_match`, so widening it widens the completeness half too, and completeness is the half that catches this attack. A looser completeness check passes more often, which is a loosening of a safety guard in the same change that loosens the additive one, and it must not be taken on the reasoning that the additive side was the target. Measured: the attack still fails, on the omitted clause's own content noun (`accepted` in the fixture parent), and it keeps failing on constructed cases where the omitted clause shares an inflected verb with the kept clause (`drops` against `dropping`, `blocks` against `blocked`), because a clause is caught by its distinctive nouns rather than by its verb. **The residual risk is named rather than closed**: an omitted clause every one of whose content words is an inflection of a word surviving elsewhere in the response would now pass completeness where it previously failed. No such case has been observed or constructed, and the bound is narrow, but it is a real widening and task 18 carries the test that would catch it moving. **Amended again 2026-08-14, for the second widening of the same half.** AC-21 exempts clause relating words from the completeness demand, which is the second change in two days to loosen the half this attack depends on, and the two compound: the first widened what counts as a match, the second removes tokens from the demand entirely. So the same rule applies a second time and for the same reason. The omission attack is **re proven under `COMPLETENESS_EXEMPT`, not assumed to survive it**, in task 19 rather than by argument here, and a constructed case is added in the newly exempt class: an omitted clause whose every word is a connective or an existing function word. The second residual is therefore stated as one sentence: **a clause carrying no lexical verb, noun, or adjective can now be omitted without failing completeness.** Such a clause can still assert something, since the copulas, auxiliaries, modals, and negators are already exempt and `which it was not` is a real negated identity built entirely from them, so the class is enlarged rather than created and the honest claim is about doors into it rather than about its emptiness. What still holds is the part this attack depends on: a fabricated decision names an entity, an action, or a property, and every word that does so is a noun, a lexical verb, or an adjective, none of which is ever exempt. The constructed test in task 19 is therefore a negated copula omission specifically, `although it was not`, rather than generic filler, because a test built from filler would exercise a weaker case than the one this amendment actually creates. Entailment remains the only guard behind the residual, which is the same position AC-11's negation and relation limit already documents. **Amended a third time 2026-08-14, for AC-22, and the rule that produced the first two amendments is applied again with one difference.** AC-22 skips a sub claim rather than widening a set, so it does not loosen either half of AC-11; what it loosens is the number of claims entailment sees, and entailment is the guard this criterion's first attack depends on. So both attacks are **re proven under the prune, not assumed to survive it**, in task 21. Read against the shipped fixture the outcome is that neither is reached: `The board approved the merger on Tuesday.` carries `board`, `approved`, `merger`, `tuesday` and `The board accepted a bribe to rush it.` carries `board`, `accepted`, `bribe`, `rush`, so neither is a subset of the other in either direction and no prune occurs in either attack. **The general property is stronger than that fixture and is what the criterion actually rests on**: AC-22 prunes only against a maximal claim, and a maximal claim is never pruned, so a pruned claim's content tokens are all present in a claim that is actually verified, and a fabricated content word can never leave the verification set by being pruned. It can only be **rebound**, which is the residual AC-22 names and pins.

- **AC-4**: The answer is made of whole draft sentences. A sub claim is never emitted, and it exists only in the trace. A sentence is emitted verbatim, with its available citations and its own sentence id, when both hold: its decomposition is valid under AC-11, and every sub claim in it is supported. If either fails, the whole parent sentence is dropped and contributes nothing; other sentences are unaffected. Draft order is preserved among the emitted sentences. Coverage then decides answered versus abstained over those sentences. A facet is covered only when one emitted sentence directly states its answer. Coverage cannot combine sentences, and a reason, context, consequence, premise, or anaphoric fragment cannot cover a decision facet unless that same sentence states the decision. One sentence may cover several facets only when it directly answers each one.
- **AC-5**: A sentence whose whole text is contained in an available cited chunk is never decomposed and never pays the decomposition call. A deterministic unit test proves the cost bound. This criterion depends on **AC-13**: a sentence carrying an inline chunk id marker can never be a substring of the chunk text it cites, so before AC-13 the shortcut was unreachable for every marker bearing sentence and the cost bound was silently dead. Experiment 0003 measured markers on 11 of 20 sentences, so the bound was dead for roughly half of them.
- **AC-6**: The debug trace shows every decomposition row and every sub claim verdict, and it answers one question for each draft sentence: did this sentence reach the answer, and if not, why. A genuine empty response appears only in `empty_decompositions`. An invalid nonempty response appears in `rejected_decompositions` with the sentence id, returned count, and one closed disposition: `over_cap`, `duplicate`, `not_additive`, or `incomplete`. Every sentence that does not reach the answer records exactly one row in `dropped_sentences` with its sentence id and one closed reason: `no_available_citations`, `decomposition_invalid`, or `unsupported_sub_claim`. A `decomposition_invalid` row always pairs with a `rejected_decompositions` row carrying the specific disposition, so the two are one event described at two levels, never two events. Rejected or unsupported claim text is not exposed. A sub claim row keeps its own `entailment` verdict so an `unsupported_sub_claim` drop can be traced to the exact claim that caused it.
- **AC-7**: A provider failure during the decomposition call returns a failed query result with a provider failure trace, consistent with the existing entailment and coverage failures. A test proves the failure contract.
- **AC-8**: Before any containment or provider call, parent citation ids are deduplicated in parent order and split into `available_citations` (ids in accepted context) and `missing_citations` (the ordered remainder). Every containment, decomposition, entailment, and output citation uses only `available_citations`. With none available, the sentence is removed without a provider call. Missing ids are trace only and can never appear in answer citations. A `missing_chunk_refs` row is recorded for every sentence with a nonempty missing set, whether or not that sentence proceeds on its available citations.

- **AC-10**: `schema_version` stays 2. The additive verification trace fields are `decomposed`, `empty_decompositions`, `rejected_decompositions`, `dropped_sentences`, and `missing_chunk_refs`. They default to empty tuples so an older constructor call remains valid. Named fields resolve, and JSON gains fields without removing or renaming any existing field. `dropped_sentences` replaces the `dropped_sub_claims` field of the earlier draft, which described an event that can no longer occur; the field count is unchanged and nothing else is renamed. The runtime does not read persisted query results, so no data migration is needed.
- **AC-11**: The lexical check is a deterministic decomposition validity test on the response as a whole. It decides whether the sub claims are a faithful division of the parent sentence, so that verifying them is the same as verifying the parent. It is not a proof that actors, negation, scope, order, or factual relations were preserved; entailment remains responsible for factual support. Tokens use Unicode NFKC, case folding, line ending normalization, whitespace splitting, and edge punctuation stripping; internal apostrophes and hyphens remain. Two tokens match when they **share a stem**, and sharing a stem is symmetric. Each token maps to its **base set**, every `shorter` the five rules below could have derived that token from, and two tokens match when their base sets intersect. The five rules, where `shorter` and `longer` name the two tokens by length: `longer` equals `shorter`; or `longer` equals `shorter` plus `s`, `es`, `ed`, or `ing`; or `longer` equals `shorter` with its final `e` removed plus `ed` or `ing` (`use` and `using`); or `longer` equals `shorter` plus a repeat of `shorter`'s own final character plus `ed` or `ing` (`ship` and `shipped`); or `longer` equals `shorter` with its final `y` replaced by `i` plus `es` or `ed` (`rely` and `relies`). A token's base set is the token itself, plus for each of the four inflection rules whose suffix that token carries, the `shorter` that rule would have started from. The **four inflection rules** still require that `shorter` to be at least three characters, measured on the untransformed token, so a base under the floor is never added to the set. **Exact equality carries no floor**: it transforms no suffix, so the floor guards nothing there, and a token already present in the parent is not new vocabulary however short it is (`db` reused verbatim must match). A function word matches only by exact normalized token equality, never by stem. **Amended 2026-08-14, and this is a correction rather than a second decision.** The five rules were previously applied in one direction only, deriving `longer` from `shorter`, so two different inflections of one word never reached their common base and never matched each other: `falls` against `falling`, `drops` against `dropped`, `decides` against `deciding`. A match required the parent to carry the bare base form. That contradicted this criterion's own words, since sharing a stem is symmetric, and it put the check at war with the job it checks, because turning a subordinate clause into a standalone sub claim converts a participle into a finite verb, which is exactly what `DECOMPOSE_SYSTEM_PROMPT` asks for. The base set is the symmetric completion of the rules already here: it introduces no new rule, so every pair it newly matches is a pair these five rules already accept in one direction, and no token is ever reduced to a lossy stem. Measured over 3,690 content tokens it matches 622 pairs the directional form missed, loses none it accepted, and invents none. [Experiment 0010](../../experiments/0010-falls-against-falling.md) names the failing case; the measurement and the rejected alternative are in [rationale.md](rationale.md), *The additive matcher*. When a sub claim token could match more than one eligible parent token, take the **first unused parent token in parent order**; the assignment is greedy and never backtracks, so two conforming builds reach the same verdict. The test has two halves, and a response must pass both. **They have deliberately different scopes**:
  - **Not additive**, scoped **per sub claim**: each sub claim is checked alone against the full parent token pool, and the pool resets for the next sub claim. Every content token in that sub claim must match an unused parent content token within that one comparison. This stops a sub claim substituting content the parent never had. The scope is per sub claim because a decomposition restates the shared subject in each part, which is normal and adds nothing: consuming those tokens response wide would reject a correct split of any sentence with a repeated subject. A function word token from the closed set in Feature design may be added without a parent match, at most two instances per sub claim, counted as instances whatever the words are.
  - **Complete**, scoped **across the whole response**: every distinct content token of the parent must match a token in at least one sub claim. Matching here is presence based, not multiset based: one occurrence in one sub claim satisfies every occurrence of that token in the parent. This stops the decomposition quietly dropping a clause, which is the omission attack of AC-1, because a dropped clause takes its content words out of the response entirely. Parent tokens in `COMPLETENESS_EXEMPT` need no match. **Amended 2026-08-14 by AC-21**: that set is `FUNCTION_WORDS` plus `CLAUSE_CONNECTIVES`, and it is read here and nowhere else. The additive half above keeps reading `FUNCTION_WORDS` alone, so the two halves no longer share one vocabulary; AC-21 states the membership rule and Feature design enumerates the members.

  A response that fails either half is invalid. Its parent sentence is dropped, no entailment call is made for it, and the trace records the disposition. **There is no per sub claim drop.** Removing a sub claim from a response would break the completeness half by construction, so the granularity question the earlier drafts asked (whole response or per sub claim) does not arise: validity is a property of the response, even though one of its halves is measured per sub claim. Reordering is allowed. The checks run in this fixed order, each without calling entailment: a malformed row (empty text after trimming) fails first as `provider.decompose`; then a genuine empty array; then more than 8 rows as `over_cap`; then a normalized duplicate row as `duplicate`. The two half test runs only on a response that survives all four, and fails as `not_additive` or `incomplete`. A response that fails the two half test gets **one decomposition retry** at the same fixed settings; if the retry is also invalid, the parent is dropped. The retry exists because an invalid decomposition is usually a stochastic paraphrase rather than a property of the sentence, and it mirrors the single schema repair attempt the other provider calls already make.
- **AC-12**: The ordered canonical facet tuple is the single output of `extract_facets(original_question)` and is stored in `GenerationTrace.facets`, then passed unchanged to answer generation and coverage. The directness rule below is unchanged from the earlier draft, but it now judges whole emitted sentences rather than sub claim fragments. That is what makes it workable: a decision stated across several clauses is one sentence, so requiring one sentence to state a facet's answer no longer rules out multi part decisions, and the no combining rule stops being a trap. Coverage uses the same fixed model constant as facet extraction and answer generation, at temperature 0. With no emitted sentences, the application creates one uncovered row per facet with reason `no emitted answer sentence` and makes no coverage call. That reason string is renamed from `no kept answer sentence`, because `kept` described a sub claim surviving on its own, which can no longer happen. Otherwise the provider returns exactly one row for every facet, in canonical facet order. Validation rejects unknown, missing, duplicate, or out of order facet ids; unknown, duplicate, or out of emitted order sentence ids; a covered row with no sentence id; or an uncovered row with sentence ids. A schema failure gets the existing single repair attempt, then fails as `provider.coverage` at `claim_verification`. The live query 4 gate requires separate decision and reason facets. Its report classifies a failure from the existing trace: a missing separate decision facet is `facet_extraction`; separate facets with the decision facet wrongly covered is `coverage_directness`; separate facets with the decision facet uncovered but an answered result is `query_state`. No new trace field is added. **A sentence stating what the system does is not a statement of a decision, and does not cover a decision facet on its own.** Experiment 0006 recorded coverage refusing exactly that shape, correctly under the rule as written, while the rule never said so: the exclusion list named a reason, context, consequence, premise, or anaphoric fragment, so the model was inferring past a list that did not reach the case. The reading is pinned here and **deliberately not added to `COVERAGE_SYSTEM_PROMPT`**. AC-16 hardened the instruction because the model was not honouring a rule; here it honours it, 0 of 11 sentences covered across experiment 0006 arm A, and under AC-4 whole sentence output a decision statement routinely carries a descriptive clause (`The project adopted hybrid retrieval, which combines BM25 with Chroma`), so an explicit description exclusion in the instruction would reject the very sentences AC-18 exists to get accepted. Tightening a stage that currently refuses everything is the wrong direction. The escalation is a number in the AC-16 shape: if a gate measurement taken after AC-18 lands shows coverage covering a decision facet with a sentence that only describes what the system does, in **2 or more of the 6 runs**, the exclusion is added to the instruction then. The count is recorded as a fraction with its denominator, the runs in which the decision facet was covered at all, so a structural zero cannot read as a clean result.
- **AC-13**: `DraftSentence.text` never contains a chunk id. `validate_draft` removes every chunk id marker from the raw text **before every other check on that text**, so the one sentence check, the empty text check, and the duplicate text check all read the cleaned string. A sentence whose text is nothing but a marker therefore fails as empty text rather than reaching output. The matcher is pinned as a literal regular expression rather than described, because a described shape is what two earlier cross checks caught AC-11 leaving ambiguous. A bare marker is `(?i)\bch_[0-9a-f]{64}\b`; a bracket group is `(?i)\[\s*ch_[0-9a-f]{64}(?:\s*,\s*ch_[0-9a-f]{64})*\s*\]`. Bracket groups are removed first, then any remaining bare marker, then the whitespace is repaired in three fixed steps: runs of whitespace collapse to one space, a space immediately before one of `.,;:!?)]}` is removed, a space immediately after one of `([{` is removed, and the result is trimmed. The punctuation steps are not cosmetic. Without them the common case leaves `chosen [ch_...].` as `chosen .`, which the token matcher tolerates (a bare punctuation token is dropped) but which reaches the reader as visibly broken prose in the emitted answer, and AC-4 emits the sentence verbatim. Three rules the shape alone does not settle: matching is **case insensitive**, so a model that uppercases a hash cannot smuggle one through even though `chunk_id` only ever emits lowercase; the comma separator tolerates any or no surrounding whitespace, since experiment 0003 recorded the model writing `", "` while the debug renderer writes `","`; and a bracket group holding anything besides markers and separators is **not** a marker group, so `[see ch_abc...]` loses only its bare marker and keeps its brackets and prose. `chunk_ids` is not touched and stays the only citation source. Because the duplicate text check reads the stripped string, two draft sentences whose prose is identical and whose markers differ now collide and fail the response as a duplicate; that is the intended reading, since the marker was never content and identical prose is genuinely duplicate. `ANSWER_SYSTEM_PROMPT` keeps naming the real bracketed ids from the evidence, because dropping that wording makes a live model invent its own ids and fail every validation attempt, and it additionally forbids writing an id inside the sentence text. Deterministic tests prove that a marker never survives into `DraftSentence.text`, in the bracketed multi id form and the bare form, that a marker only sentence fails as empty, that a mixed bracket group keeps its prose, and that the duplicate collision above is reached; the prompt half is measured by the live gate, not by a unit test, since it changes how often the strip fires rather than whether it works.
- **AC-14**: The self corpus gate reads a **frozen corpus fixture**, never the live `docs/specs/` tree. A committed script, `docs/experiments/data/build-self-corpus-fixture.sh`, generates the fixture into `docs/experiments/data/self-corpus-fixture/`, whose own corpus root is that directory and whose records therefore live at `docs/experiments/data/self-corpus-fixture/docs/specs/`. That placement is outside `docs/specs/`, so `adapt` at the repository root cannot discover it: discovery reads `corpus_root/docs/specs` and iterates its direct children only, so a tree nested deeper is structurally invisible rather than merely filtered. The fixture excludes the `0010-abstention-verification-reliability` directory. **Amended 2026-08-14 by spec 0012 AC-8, which states the membership rule this exclusion was resting on without recording.** A spec is excluded when its own prose contains the gate's queries, its expected records, or its expected states; everything else is copied in. This spec is excluded under exactly that rule and no other, because it carries the gate's literal query text and its expected record and state in both `index.md` and `rationale.md`, which is unavoidable in the spec where the gate was designed, and which is the same gap this criterion's own Follow-up item names. The rule is deliberately not "exclude whatever is under active build": that reading would make fixture membership change as specs finish, which is drift in a fixture whose purpose is being frozen. Beside it the script writes `manifest.json`, whose shape is pinned in Feature design, carrying the source commit, the excluded spec, a **sha256 over the raw bytes of each copied file**, and the gate's queries with their expected record and expected result state. Raw bytes rather than the adapter's own `fingerprint()`, because this hash exists to detect drift of the fixture input; `fingerprint()` also moves on an `ADAPTER_VERSION` bump, which would report adapter churn as corpus drift. Regenerating the fixture against a changed working tree therefore produces a visible diff rather than a silent change to the measurement input. The gate's queries and their expected records live in that manifest, outside the corpus entirely, and never in a spec. **Stated assumption, verified once, not assumed forever**: the fixture is a faithful stand in for the frozen live corpus only for the chunk text the gate reads, not for the whole adapted record. `_extract_code_paths` resolves inline code spans against the corpus root, and the fixture root holds no `src/` or `tests/` tree, so the `src/decision_memory/...` paths every spec cites do not resolve there and each record's `evidence` set is smaller and its `mentions_unresolved` count higher than a live adaptation would produce. Task 11 checks once that a record's active chunk set is identical between a live and a fixture adaptation; identical chunks confine the divergence to the `evidence` field, which the gate's answers do not read. A difference invalidates the fixture and is a finding, not a pass.
- **AC-15**: The self corpus gate's oracle is state, a **co located citation**, and an **abstention cause**, and the gate runs under `evaluate` with its battery loaded from `manifest.json` rather than from code. Each manifest query gains two fields. `expected_value_paths` is an ordered tuple of value path prefixes built on the `QueryOracle.required_value_path_prefixes` semantics, **co location included**: a prefix must be matched by a citation whose record is that query's `expected_record`, and a prefix matched only by an unrelated record's citation does not satisfy the oracle. For a manifest battery the match is additionally **scoped to the covering sentence**: the matching citation must belong to a sentence that at least one covered coverage row names. The existing rule scans every citation in the answer, and record scope alone cannot tell a decision from a caveat once more than one sentence is emitted, which is this criterion's own failure one level down; the JobPilot battery keeps the existing whole answer semantics unchanged, so nothing already built moves. The decision query carries `["decision.chosen"]`, so citing any chunk of `DM-0008` no longer passes; the sentence doing the covering must cite the chunk that holds the decision statement. `expected_abstention` applies only to a query whose `expected_state` is `abstained`, and has two closed values: `uncovered_facet` (at least one sentence was emitted and at least one facet came back uncovered) and `no_emitted_sentences` (no sentence reached coverage, so the AC-12 deterministic uncovered rows applied). The reason query carries `uncovered_facet`. **The abstention half is the more load bearing of the two.** Experiments 0002, 0003, and 0004 each recorded a query that met an `abstained` expectation only because every draft sentence had been dropped, which satisfies the state while proving nothing about abstention; separating the two causes is what makes an abstention gate mean what it says. The cause is read from the existing trace and adds no field, and it is **read only from a claim verification abstention with a nonempty coverage tuple**: `no_emitted_sentences` when every coverage row carries the deterministic reason `no emitted answer sentence`, `uncovered_facet` otherwise. That guard is not a formality. A retrieval stage abstention carries an empty coverage tuple, and every row of an empty tuple satisfies any test, so without it a query that abstained before generation ever ran would be reported as the deterministic no sentence case and quietly satisfy the gate. An abstention at any other stage is neither cause and fails the gate with that stage named. The battery loader **fails loudly on a missing or unrecognized manifest key** rather than defaulting, so a manifest written before an oracle was strengthened cannot quietly run the gate under the old weaker oracle; a silently weakened oracle is the exact failure this criterion exists to close. It also **fails loudly on an unsatisfiable oracle**, checked once after adapt and ingest and before any query runs: every `expected_record` must exist in the adapted record set, and every `expected_value_paths` prefix must match at least one chunk of that record. A typo'd record id or a prefix no chunk carries would otherwise fail the gate forever with nothing to separate a broken pipeline from a wrong manifest, which is the diagnostic ambiguity AC-12's failure classifier exists to prevent elsewhere. The bar is two separate `--runs 3` batches, 6 runs. The abstaining query must meet its expected state **and** its expected cause in 6 of 6, unconditionally, matching AC-2 and AC-3. The answering query's 6 of 6 is **provisional**: this is the spec's first bar that requires an answer rather than an abstention, and the two are not equally hard, because a stochastic pipeline fails toward abstention. It is confirmed or relaxed from the first measurement taken after the task 13 calibration, the way AC-9's 5 of 6 was set from observed query 1 variance rather than chosen, and task 15 records the measured figure. **Both halves are expected to miss until task 13 lands**, and for the same reason: experiment 0004 recorded the reason query abstaining from `no_emitted_sentences` rather than the `uncovered_facet` its manifest pins, because sentences have to survive to reach coverage at all. The bar is unconditional, the early failure is expected, and those are not in tension: a gate that fails honestly is working, and only a gate that passes wrongly is a defect.

- **AC-20**: A rejected decomposition names the token it stopped on, and it does so for **both halves** of the AC-11 validity test. `RejectedDecomposition` gains two defaulted trailing fields, `failure_token` and `failure_side`, following the AC-19 precedent that keeps an older constructor call valid. `failure_token` is the single token the check stopped at. `failure_side` is one closed value: `sub_claim` when the additive half stopped on a sub claim token no unused parent token matched, `parent` when the completeness half stopped on a parent content token no sub claim matched, and empty for `over_cap` and `duplicate`, which stop before any token is examined. **A single token is not claim text**, so the no rejected claim text rule is intact for the same reason the AC-19 category is, and the closed side value is a category rather than prose. **Covering both halves is the point.** `additive_failure` is set only when the disposition is `not_additive`, and experiment 0007's 18 drops were **11 `incomplete` and 7 `not_additive`**, so a field modelled on `additive_failure` alone would be blind to the majority case. Nothing about the disposition, the retry, `RETRYABLE_DISPOSITIONS`, or any drop path depends on either field; both are observational. **The carrying shape is pinned, because neither half check has a return slot left.** `sub_claim_is_additive_free` already spent its one signature change on the AC-19 category, so it returns `(category, token)` or `None`, and `response_is_complete` returns the offending parent token or `None`. `classify_decomposition_detail` then returns a frozen `DecompositionVerdict` holding `disposition`, `additive_failure`, `failure_token`, and `failure_side`, **not a four value tuple**. Three of those four are closed vocabularies that share nothing but their type, and two adjacent same typed values read positionally in the wrong order is a defect this project has already shipped once, in commit `004dc3c`, where mypy could not see it and the evaluation harness had to. The closed sets are pinned on the verdict: `disposition` over `over_cap`, `duplicate`, `not_additive`, `incomplete`, or none; `additive_failure` over `content_token`, `function_word_overrun`, or empty; `failure_side` over `sub_claim`, `parent`, or empty. `failure_token` is the only free string on it, and it is a token rather than claim text, which is what keeps the no claim text rule intact. **`classify_decomposition` is a derivation of `classify_decomposition_detail`, returning `verdict.disposition`, and never a parallel implementation.** Two functions computing one verdict independently is the second traversal that can disagree with the verdict, which AC-19 rejected and which experiment 0010's instrument caught on its first run. - **AC-21**: The completeness half does not demand a parent match for a word whose job is relating one clause to another. **The two halves of AC-11 no longer read one set.** `FUNCTION_WORDS` is unchanged and keeps serving `tokens_match` and the additive half; a second set, `COMPLETENESS_EXEMPT`, is the union of `FUNCTION_WORDS` with a new closed constant `CLAUSE_CONNECTIVES`, and it is read by `response_is_complete` and by nothing else. **The membership rule is stated before the members, and the members are enumerated from the rule rather than from the failures.** A word belongs to `CLAUSE_CONNECTIVES` when it relates one clause to another, so that a decomposition into standalone one clause statements leaves it nothing to do. That is decidable by construction: split the sentence and ask whether the word still has work. The set is enumerated exhaustively in Feature design from four closed grammatical categories plus the correlative markers, and a word is added by re reading the rule, never by observing the next failure. **One exclusion is part of the rule**: a word whose primary use is as a lexical verb, noun, or adjective stays a content token even where grammar lists a marginal connective use for it, which keeps `provided`, `given`, `granted`, `considering`, and `seeing` out. **A word with a second use is judged by the second exclusion rule, not waved through.** The check reads a bare token and cannot tell which use is present, so the question is what the other use costs if it is the one there: a second use that is truth conditional (a quantity, a comparison, a time, a degree, a manner) keeps the word demanded, and a second use that is merely another discourse relation leaves it exempt. That rule removes seventeen members of the first enumeration, including every temporal subordinator and every correlative marker except `whether`. **The rule is stated over a function, not a part of speech**, because the three measured tokens span three categories: `where` is a relative adverb, `while` is a subordinating conjunction, and `instead` is a conjunctive adverb inside the complex preposition `instead of`, whose `of` is already exempt. A rule stated over subordinating relative adverbs would ratify an edit that still fails on `instead` ([experiment 0012](../../experiments/0012-the-other-three-abstentions.md)). **The additive half deliberately does not share the list**, and this is a decision rather than an omission: every measured AC-11 failure is `failure_side=parent`, so nothing measured implicates the additive half, and that half is the guard behind AC-2, the only criterion in this chain green on live evidence. Moving these words into `FUNCTION_WORDS` would convert each from budgeted under `MAX_ADDED_FUNCTION_WORDS` to free, which is the trade OD-8 refused. The visible consequence is stated rather than left to be discovered: a connective outside `FUNCTION_WORDS` is still a content token to the additive half, so a sub claim introducing `while` with no parent match still fails as `not_additive` with `additive_failure=content_token`. That is the intended reading, since a decomposition adding a clause relation the parent never had is adding content, and `failure_token` records it if it occurs. **`tokens_match` is not touched at all**, so the matcher both halves share keeps the exact semantics OD-8 measured, and no safety argument about it has to be made a second time. **The widening is bounded and the bound is named, not closed**: an omitted clause every one of whose words is exempt would now pass completeness. **The bound is that the class already exists, not that it is empty**, and the weaker statement is the true one. An all exempt clause can carry a real proposition, because `FUNCTION_WORDS` already exempts the copulas (`is`, `are`, `was`, `were`, `be`, `been`, `being`), the auxiliaries (`has`, `have`, `had`, `do`, `does`, `did`), the modals, and the negators (`not`, `no`, `never`, `nor`), and a copula plus a negation is a complete predication with no lexical verb, noun, or adjective in it. `which it was not` is exactly that shape and is wholly exempt under the set as it stands today, so what AC-21 adds is new syntactic doors into an existing class rather than the class itself. Using a new member: `although it was not` would be fully exempt, and it asserts something. What holds the line is narrower than a claim about propositions: **a clause naming any entity, action, or property carries a noun, a lexical verb, or an adjective, and none of those is ever exempt under either rule**, so the omission attack of AC-1, which hides a fabricated decision, cannot be built out of exempt words alone. Task 19 re runs both AC-1 attack tests against the widened exemption and adds a constructed case in the new class, exactly as task 18 re ran them against the widened matcher rather than assuming they survived it. Deterministic tests cover: every member of the pinned `CLAUSE_CONNECTIVES` tuple exempt on the completeness side, each of the three measured tokens specifically, the same members still failing the additive half as `content_token`, `FUNCTION_WORDS` unchanged by value, `tokens_match` unchanged in behaviour, and the excluded words (`provided` and its four companions) still demanded.

- **AC-22**: A sub claim that is a strict lexical weakening of a sibling is never sent to entailment. This is the granularity criterion the spec did not have. A decomposition can be valid under AC-11 and still return a fragment too atomic to be grounded: [experiment 0013](../../experiments/0013-the-connectives-cleared-and-entailment-is-next.md) measured `The decision was made.` coming back `unsupported` 3 of 3 while the three siblings that state the same thing with its object attached came back supported every time, and one unsupported sub claim drops the whole parent. Experiment 0004 recorded the same shape as `The adapter warns.` before any of the AC-11 work began. **Pruning happens after the AC-11 verdict and before the first entailment call, and it changes no verdict AC-11 reaches.** **It runs in two passes, and the second pass is what makes the safety argument hold rather than merely sound convincing.** The first pass finds the **maximal** sub claims, the ones no sibling subsumes. The second prunes a candidate only when a **maximal** claim subsumes it. A candidate subsumed only by a claim that is itself pruned is **not** pruned. Without that restriction a chain (C under B, B under A) leaves C's recorded sibling gone from the verification set, and the criterion's guarantee quietly degrades into an assumption that `tokens_match` composes transitively, which is not generally true of a base set intersection: two sets can each meet a third without meeting each other. **`subsumed_by` therefore always names a claim that faces entailment**, which is a property of the algorithm rather than a hope about the matcher.

  **A content token here means a token outside `FUNCTION_WORDS`**, the additive half's vocabulary, and never `COMPLETENESS_EXEMPT`. That is pinned rather than inferred from AC-21 saying its own set has exactly one reader. A clause connective is content to this relation, for the same reason it is content to the additive half: a candidate that drops a clause relation its sibling carries is not saying less, it is saying something else.

  A sub claim is **subsumed** by a sibling when all three conditions hold:
  - **Strict content subset**: every content token of the candidate matches a distinct content token of the sibling through `tokens_match`, and the sibling carries at least one content token the candidate does not. The walk is greedy first unused in sibling order, the same tie break AC-11 fixes, so two conforming builds reach the same verdict. `tokens_match` is read and not touched, for the third time in this chain.
  - **Matching polarity and modality**: the candidate and the sibling carry the same set of `POLARITY_MARKERS` tokens. That constant is a **named subset of `FUNCTION_WORDS`**, the four negators plus the nine modals, derived from it rather than written beside it, so a word cannot be a function word in one place and a polarity marker in another. Without this condition `The decision was made.` is a strict subset of `The decision was not made to use X.` and of `The decision may be made to use X.`, and in both the sibling coming back supported says nothing about the candidate.
  - **Order preserving**: the matched sibling tokens appear in the same relative order as the candidate's own tokens. **This condition reads the assignment condition 1 already produced and never computes a second matching**, pinned in the AC-20 shape and for the AC-20 reason: match, then test a property of the match, is the structure that shipped a disagreement once in commit `004dc3c`, and two traversals that can disagree about which parent token a sub claim token took would make the verdict depend on which one a caller happened to ask.

  **The three conditions narrow argument rebinding and do not close it, and that is stated here rather than implied.** Rebinding is a content token reattached to a different object, and no lexical relation can see it, because deciding it means deciding predicate argument structure. The boundary case is constructed and pinned as a test in task 21, in the shape task 19 used for `although it was not`, and it is a case that **passes all three conditions and is wrong**, not one that is refused: against the sibling `The team chose client side refetch and rejected background polling.`, the candidate `Client side refetch was rejected.` carries `client`, `side`, `refetch`, `rejected` at sibling content positions 3, 4, 5, and 6, so it is a strict subset in order, and neither side carries a negator or a modal. It prunes, unchecked, and it asserts the opposite of the evidence. A test asserting a **refused** prune would pin nothing about the residual; it would record only that one sentence fails one condition.

  **What bounds the residual is a property of the relation, not a marker set.** Subsumption is strict, so the subsuming claim always matches more content tokens than the candidate; over a finite response that ordering cannot cycle, so a maximal claim always exists and **at least one sub claim always faces entailment**. The two pass rule then makes every pruned claim's recorded sibling one of those. So a pruned claim's content tokens are all present in a claim that is **actually verified**, not merely in some claim, and a fabricated content word can never leave the verification set by being pruned. The residual is exactly this: the argument binding of a **non maximal** sub claim goes unchecked. Whether that can carry a fabrication the surviving maximal siblings all miss is the under splitting question the Follow-up already tracks, and this criterion does not answer it.

  **The cost of refusing to prune is exactly today's behaviour**, because the prune is only permission to skip a check. Every condition can therefore be conservative for free, which is why three of them are cheaper here than one would be anywhere else in this spec.

  **A pruned sub claim is recorded, because the prune rate is otherwise unmeasurable by construction.** It keeps its `decomposed` row and its position, so AC-6's contiguous ids are unaffected, with `entailment` carrying a fourth closed value, `pruned`, and one defaulted trailing field, `subsumed_by`, naming the sub claim id of the maximal sibling that subsumed it (empty for every other row). When several maximal siblings subsume it, `subsumed_by` names the first in provider order. **The deterministic containment check still runs on a pruned claim**, and only the entailment call is skipped. Containment is free, it never rejects (AC-5), and a pruned claim that turns out to be contained in a cited chunk is worth seeing in the trace, so the row carries a truthful `contained` and its matching citations rather than a default nobody can read. **The row keeps the claim text, and that is deliberate rather than an oversight of the no claim text rule**: that rule governs `rejected_decompositions`, and `decomposed` rows have carried full sub claim text for supported and unsupported claims since task 1. A pruned claim belongs to a **valid** response, so nothing about it is rejected text.

  Deterministic tests cover: the experiment 0013 fragment pruned against its sibling and its parent surviving; the rebinding boundary case above pruning, pinned as the documented residual; **the chain case, C under B under A, where C is not pruned because its only subsumer is not maximal, and B is**; a negated sibling refusing the prune; a hedged sibling refusing it; an out of order candidate refusing it; equal content sets refusing it in both directions, so mutual subsumption cannot occur; the maximal sub claim never pruned; every `subsumed_by` on a response naming a claim whose row is not itself `pruned`, asserted as a property over a constructed multi level response rather than on one example; a clause connective treated as content by this relation while `COMPLETENESS_EXEMPT` still exempts it on the completeness half; a pruned row carrying a truthful `contained` and citations; `POLARITY_MARKERS` a proper subset of `FUNCTION_WORDS` by value; `tokens_match`, `FUNCTION_WORDS`, `COMPLETENESS_EXEMPT`, `classify_decomposition_detail`, and `RETRYABLE_DISPOSITIONS` unchanged in behaviour; and the trace row carrying `pruned` with its `subsumed_by`.

Nothing has ever established that query 4's 6 of 6 rests on a verdict rather than on the same thing, and AC-2 is the one criterion in this chain treated as green on live evidence, so leaving it unexamined while examining query 5 would be choosing which answer to learn. A cause failure on either is recorded against this criterion and is not read as a verification regression.
- **AC-24**: A figure a decision rests on is measured over **four `--runs 3` batches, 12 runs**, and a figure below that denominator cannot settle a criterion. Two batches stay the routine denominator for a re measurement that confirms known behaviour. The policy is **forward looking**: a bar is re measured at 12 the next time a task touches it, not all at once, so AC-2 and AC-3 move to 12 in this round because AC-23 changes what they demand, while AC-9 and AC-15 keep their existing denominators until something touches them. **The number is four batches rather than more runs per batch, because the variance is not one thing.** One `evaluate` invocation adapts once, ingests once, then runs every fixture `--runs N` times (`evaluation.py:494-535`), so the store is held constant inside a batch and varied between batches. Experiment 0013's own table separates the two without any new runs: `query-5-uploaded-files` at 2 of 3 and `assertion-rationale-summary` at 1 of 3 vary with the store constant, which is provider variance, while `query-1-private-beta-gate` at 0 of 3 then 3 of 3 splits cleanly on the store boundary. **Eighteen runs was rejected on that separation rather than on cost.** Averaging over both would fold a store effect that moved one fixture by three runs of three into the same denominator as a provider effect that moved another by one of three, and the larger of the two would disappear into it. The store split is a suspected correctness defect and is enrolled in Follow-up, not absorbed into a run count. **The reading rule is part of the criterion**: an experiment reports every rate with its denominator and names which of the two it is, and a capability figure measured over fewer than 12 runs is recorded as an observation that no criterion may be set or moved from. **The aggregate shape is pinned**, for the reason AC-14 pinned the fixture manifest, AC-15 pinned the manifest keys, and AC-19 pinned the experiment 0007 record: this figure is read later by whoever confirms a bar, and two builds inventing two shapes is the gap those pins exist to close. Four batches are four separate `evaluate` invocations, so nothing aggregates them automatically and the experiment does it by hand from the per batch reports plus the trace directories. Each experiment carries one table with a row per fixture and these columns, no others added silently: the four per batch fractions in invocation order, the total over 12, the **within batch spread** (the count of batches whose result is neither 0 of 3 nor 3 of 3, which is the provider side), the **between batch spread** (the count of distinct per batch results, which is the store side), and the expected state. A fixture whose two spreads point different ways is named in prose beneath the table rather than left for a reader to notice.

## Decision

**Chosen option**: Option 1 revised: sub claim decomposition as a verification check on the parent sentence, with whole sentence output, plus strict complete facet coverage.

The **verification unit** is the sub claim. The **output unit** is the sentence. The earlier draft made these the same thing, and experiment 0002 showed that this is the flaw: splitting the answer makes coverage unreliable in both directions at once, accepting fragments that say too little and refusing fragments that each say part of the truth.

The application first resolves the parent citation ids against accepted context. A sentence fully contained in one available cited chunk keeps the whole sentence path and only its available citations. Every other sentence with available evidence is decomposed by `gpt-4o-mini`. The response is then tested for validity as a whole under AC-11: it must add no content to the parent and omit none of it. The two directions read two vocabularies (AC-21). The additive direction reads the closed function word set, unchanged, because it is the guard against a substituted word. The completeness direction additionally exempts the words whose job is relating one clause to another, because a decomposition into standalone clauses dissolves them by construction and demanding a match for one drops a sentence for doing what it was asked to do. An invalid response drops its parent sentence and makes no entailment call. In a valid response every sub claim is verified alone, containment first, then entailment. If every sub claim is supported, the parent sentence is emitted verbatim with its available citations. If any sub claim is unsupported, the parent sentence is dropped whole. Sub claims never reach output; they exist to decide the fate of the sentence they came from.

Between the validity verdict and the first entailment call, a sub claim that is a strict lexical weakening of a sibling is skipped (AC-22). A decomposition can be faithful and still hand entailment a fragment carrying no object, and `The decision was made.` is not something evidence can support however true the sentence it came from is. Skipping it is safe in the one direction that matters, because every content token it carries is carried by the sibling that stays and is still verified. It is not safe in every direction, and the spec says so: a lexical relation cannot decide which object a word is bound to, so a non maximal claim's binding goes unchecked, and that residual is named and pinned as a test rather than argued away.

The abstention gates stop reading a state alone (AC-23), and a figure that settles a decision is measured over twelve runs rather than six (AC-24). Both come out of one experiment reading its own numbers honestly: a gate can pass because everything was dropped before a verdict was ever reached, and two batches of the same code disagreed on three fixtures out of eight.

Generation is told which part of the record each evidence chunk is (AC-18). Every accepted chunk already knows its `value_path`, and generation was the one stage that never received it, so the model was asked what was decided from prose that never said it was a decision. Each evidence block now carries a plain words field label above the chunk text, and the answer prompt asks a decision facet to be answered with the decision. Coverage is deliberately not touched: it was reading the directness rule correctly, and the rule, not the stage, was silent on this shape.

Coverage remains binary and independent over the canonical facet tuple. A query is answered only when every facet is directly answered by one emitted sentence. Coverage never composes an answer across sentences. Reasons alone cannot cover a decision facet. This is a targeted enforcement of spec 0007 AC-15. It does not solve query 2 citation completeness, because that missing record is not represented by a fixed facet and remains a follow up.

## Feature design

**Data model sketch**:

New entity, the sub claim, held only in the verification trace, no persistence:

- `sub_claim_id`: str, `f"{sentence_id}.{i+1}"`, 1 based over the decomposition response order. A duplicate under `normalize_for_containment` invalidates the whole response. Ids are contiguous, because a sub claim is never removed from a valid response
- `sentence_id`: str, the parent DraftSentence
- `text`: str, the atomic claim
- `contained`: bool, whole sub claim verbatim in a cited chunk
- `entailment`: str, one of `skipped` (contained, no model call), `supported`, `unsupported`
- `reason`: str, the entailment reason, empty when skipped
- `citations`: tuple of available chunk ids that support this sub claim. Trace only, since a sub claim is never emitted. A contained sub claim narrows to the matching available chunks; an entailment grounded one keeps all available citations because `entail_verdict` has no per chunk attribution

There is no `kept` field. A sub claim does not survive or fail on its own; it contributes its verdict to the parent sentence, and the parent is what survives or fails.

New entity, the dropped sentence, held only in the verification trace:

- `sentence_id`: str, the draft sentence that did not reach the answer
- `reason`: str, one of `no_available_citations`, `decomposition_invalid`, `unsupported_sub_claim`
- no claim text is recorded

New entity, the rejected decomposition, held only in the verification trace:

- `sentence_id`: str, the parent sentence
- `returned_count`: int, the number of rows returned before rejection
- `disposition`: str, one of `over_cap`, `duplicate`, `not_additive`, `incomplete`
- `additive_failure`: str, defaulted to empty, one of `content_token`, `function_word_overrun`, or empty (AC-19). It is set only when `disposition` is `not_additive`. **It is read off the point the existing check already stops at, and nothing scans further.** `sub_claim_is_additive_free` returns on the first token that fails, in token order, so the category is the cause of that token on the first sub claim that failed. A sub claim carrying both an over budget function word and a later unmatched content token records whichever came first in token order, and that is the pinned reading rather than an accident: reporting the other would need a full scan, which would change the function from an early return into a survey and make the category a second traversal that could disagree with the verdict. The consequence is stated so a reader of the figure knows what it is: this counts **first causes**, not causes present, so a `function_word_overrun` share is an **upper** bound on the sentences the tolerance could reach: a sub claim rescued by a larger budget can still fail on a later unmatched content token, a later sub claim can fail in its place since `classify_decomposition` scans them all, and a response whose sub claims all pass the additive half can still fail `response_is_complete` as `incomplete`. A `content_token` share is a **lower** bound on the ones it cannot reach, since some `function_word_overrun` cases are also unreachable. Both bounds are conservative in the same direction: they cannot make calibration headroom look larger than it is. It is a closed category, never claim text, so the no claim text rule above is unchanged. It exists because the additive tolerance can only ever move the `function_word_overrun` share, and the two have never been separated

`VerificationTrace` gains five additive fields:

- `decomposed`: tuple of sub claim rows, for every sub claim of a valid response, default `()`
- `empty_decompositions`: tuple of sentence ids whose provider response contained zero sub claims, default `()`
- `rejected_decompositions`: tuple of invalid whole responses, with no rejected claim text, default `()`
- `dropped_sentences`: tuple of dropped sentence rows, with no claim text, default `()`
- `missing_chunk_refs`: tuple of (sentence_id, missing chunk ids), the upstream signal when generation cited chunks that retrieval did not surface, default `()`

**State transitions** (verification pipeline):

Per draft sentence, resolve available and missing citations. With no available citation, drop the sentence, record the missing ids, and record a `no_available_citations` row. Otherwise run whole sentence containment against available chunk text only; if it passes, emit the parent with its available citations and make no further call. If it fails, decompose using the same available evidence, then test the response for validity: genuine empty, then over cap, then duplicate, then the two half lexical test of AC-11 (not additive, then complete). An invalid response records its `rejected_decompositions` disposition and a `decomposition_invalid` row, drops the parent, and makes no entailment call. A valid response has every sub claim verified against available evidence, containment first then entailment. If every sub claim is supported, emit the parent sentence verbatim with its available citations. If any sub claim is unsupported, drop the parent and record an `unsupported_sub_claim` row. Preserve draft order across the emitted sentences. If no sentence remains, create deterministic uncovered rows without a coverage call; otherwise run coverage against the unchanged canonical facet tuple and the emitted sentence tuple. Any uncovered facet abstains. An abstained result exposes no public sentences or citations, while its trace retains the verification rows.

**API surface**:

No new command, no new flag, no new endpoint. The debug trace and JSON output gain the five additive verification fields above. Top level `QueryResult` is unchanged, `schema_version` stays 2.

| Surface | Change |
|---|---|
| `query --debug` | gains a Sub claims section listing sub claim rows, genuine empty responses, invalid response dispositions, dropped sentence rows, and missing chunk refs |
| JSON `QueryResult.trace.verification` | gains `decomposed`, `empty_decompositions`, `rejected_decompositions`, `dropped_sentences`, `missing_chunk_refs` |
| `evaluate` | gains `--battery PATH`, a fixture battery read from a manifest file, whose parent directory is the corpus root (AC-15). Without it the built in JobPilot battery runs exactly as today; the runs, report, and exit codes are unchanged either way |

**Provider contracts**:

Available evidence is assembled once per parent. Scan `DraftSentence.chunk_ids` in order, keep the first occurrence of each id, and look it up only in accepted context. Provider evidence uses available citation order. Each block is `CHUNK {chunk_id}:\n{text}`, joined with `\n\n---\n\n`. Containment, decomposition, and entailment all use this same lookup and order.

Decomposition receives the exact parent sentence plus the available evidence blocks. It uses `gpt-4o-mini`, temperature 0, and the existing single schema repair attempt. Its structured response is `{"sub_claims": [{"text": "nonempty string"}]}`. The provider prompt says at most 8, but the response schema leaves the array unbounded so the application can classify an over cap response instead of mislabeling it as provider failure. Text is trimmed and provider order is preserved. Empty text after trimming is malformed. Text repeated under `normalize_for_containment` rejects the complete response as `duplicate`. A malformed row fails as `provider.decompose`. A valid empty array removes the sentence and records a genuine empty. An over cap or duplicate response removes the sentence and records its closed rejection disposition.

**Prompt constants.** Prompt text is a spec constant, not a build time choice, so the exact shipped strings are recorded here. Two of them changed after the first draft and are written out in full.

`DECOMPOSE_SYSTEM_PROMPT` asks for both directions the validity test measures. The additive direction alone is not enough: a response that omits a clause is rejected as `incomplete` and takes its whole parent down, so a prompt that never asks for completeness makes the AC-11 hard gate fire on correct behaviour. The shipped text is:

```text
Split the candidate sentence into atomic factual sub claims. Each sub claim
must be one atomic assertion stated nearly verbatim, using only words and
facts already present in the candidate sentence. Return at most 8 sub claims.
Never introduce content that is not in the candidate sentence. Cover the whole
sentence: every clause of it must appear in some sub claim, and leaving a
clause out is an error. If the sentence is already a single atomic claim,
return it as one sub claim.
```

`ANSWER_SYSTEM_PROMPT` is reworded for AC-13 and again for AC-18. It keeps naming the real bracketed ids, which is load bearing (without that wording a live model invents its own ids and every validation attempt fails), and it moves them explicitly into the `chunk_ids` field while forbidding them in the sentence text. AC-18 adds the decision framing instruction, points the model at the `Field:` line, and forbids copying that line into the sentence. The shipped text is:

```text
Write short factual answer sentences that directly answer the given facets,
using ONLY the provided evidence chunks. Every sentence must be a single
complete sentence and list 1 to 8 chunk ids it is directly supported by in
the chunk_ids field, copied exactly as shown in brackets in the evidence.
Never write a chunk id inside the sentence text itself. Each chunk's Field
line says which part of the record that chunk is; never copy a Field line
into the sentence text. When a facet asks what was decided, answer it with
the decision the record chose, stated as a decision rather than as a
description of how the system works. Number the sentences S1, S2, and so
on. Never invent facts outside the evidence. If the evidence cannot answer
a facet, write nothing for it.
```

The prompt is the soft half of AC-13 and the strip is the hard half. The strip is what makes the guarantee: experiment 0003 measured a marker on 11 of 20 sentences, and the prompt only lowers how often the strip has to fire. **That figure is the baseline before any prohibition existed**, not evidence that a prohibition fails. The sentence forbidding a chunk id in the sentence text was introduced by the task 9 commit, after experiment 0003 measured, and the post prohibition echo rate has never been measured, because the strip removes markers before anything records the text. Any later argument about whether a prompt prohibition is enough has to reckon with that absence of evidence rather than cite 11 of 20.

**Generation evidence blocks** (AC-18). This shape was never pinned, and it has already diverged from the per parent verification shape above; both are recorded here so the divergence is documented where the shapes live. Blocks join with `\n\n---\n\n`, and each block is:

```text
CHUNK {index} ({chunk_id})
Field: {label}
{text}
```

The `Field:` line is omitted entirely when the chunk's `value_path` has no mapping entry, so an unmapped path degrades to the previous behaviour rather than introducing an unmatchable token. **The three values travel as one sequence of `(chunk_id, value_path, text)` triples, not as a third parallel list.** `generate_answer` takes ordered ids and ordered texts today and zips them with `strict=False`, so a length mismatch misaligns silently instead of failing; adding a third parallel sequence would widen that class rather than leave it alone. A triple removes it, and the `QueryDependencies.generate_answer` signature in `query.py` changes with it. The verification path is untouched and keeps its own `(chunk_id, text)` pairs. **The chunk id notation stays in parentheses.** `ANSWER_SYSTEM_PROMPT` says the ids are shown in brackets, which is inaccurate about this rendering and is deliberately left alone by the task that rewrites this block; the reasoning is in AC-18 and the fix is scheduled in Follow-up behind experiment 0007.

**The field label mapping** (AC-18) is a spec constant, rendered by one named function, `field_label` in `openai_generation.py`, so a reader and `/check review` have one place to check. A chunk's `value_path` is set in exactly one place, from exactly these nine `add()` calls in `chunking.py`:

| value path | label |
|---|---|
| `context.problem` | the problem this record faced |
| `context.triggering_change` | the change that triggered this record |
| `decision.chosen` | the decision this record chose |
| `decision.alternatives[i]` | an alternative this record considered and did not choose |
| `why[i]` | a reason this record gives for its decision |
| `rationale_summary` | this record's summary of its own reasoning |
| `consequences.positive[i]` | a positive consequence this record expects |
| `consequences.negative[i]` | a negative consequence this record accepts |
| `body[i]` | other prose from this record |

The index rule is stated once and applies to every indexed path: **the index is not rendered**, and **the lookup ignores it**. The table above is written with `[i]` for readability, while a real chunk always carries a literal index, `why[0]` and never `why[i]`, so the transform is pinned rather than described: **look up the substring before the first `[`, and ignore everything from that bracket onward**. `why[0]` and `why[3]` therefore both find the `why` entry and both render `a reason this record gives for its decision`. An ordinal carries no meaning to a reader, and an echoed number would be noise in the sentence text. A path with no bracket is looked up whole. This is pinned because a described transform is exactly what two earlier cross checks caught AC-11 leaving ambiguous. The nine paths are pinned as a constant tuple beside the mapping, a deterministic test proves `field_label` covers every entry of that tuple, and `/check review` checks the tuple still matches `chunking.py`, which is the same named owner shape AC-17 uses. `title` and `supersedes` are absent on purpose: they appear only in the missing field source check and never become chunks. `decision.alternatives[i].title` and `decision.alternatives[i].rejection_reason` are absent for the same reason: they are source paths, and the chunk they belong to carries `decision.alternatives[i]` with the composed alternative text.

The lexical test runs on the decomposition response as a whole against the parent sentence, in both directions, under the exact normalization, stem, bound, and ordering rules of AC-11, which is the single normative statement of the matcher. This section adds only the token set it refers to.

The function word set is closed and exhaustive, a spec constant rather than a grammatical category the builder extends. It is exactly `a`, `an`, `the`, `and`, `that`, `which`, `is`, `are`, `was`, `were`, `be`, `been`, `being`, `has`, `have`, `had`, `do`, `does`, `did`, `can`, `could`, `will`, `would`, `shall`, `should`, `may`, `might`, `must`, `to`, `of`, `for`, `with`, `by`, `as`, `at`, `on`, `in`, `from`, `about`, `so`, `but`, `or`, `if`, `because`, `when`, `then`, `there`, `it`, `this`, `these`, `those`, `their`, `not`, `no`, `never`, and `nor`. Any token outside this set is a content token. In the additive direction, checked per sub claim against a fresh parent pool, a content token must find an unused parent match. In the completeness direction, checked across the whole response by presence, a distinct parent content token must appear in at least one sub claim. Function words are bounded in the additive direction. Closing the set errs toward dropping a sentence, which is the safe direction, and an unlisted word that shows up in practice is a spec edit, not a build time judgment.

**The completeness exemption set** (AC-21). The completeness direction reads a second, wider set, and the additive direction does not. This is the one place the two halves of AC-11 diverge, and the divergence is the decision:

```python
CLAUSE_CONNECTIVES: frozenset[str] = frozenset({...})
COMPLETENESS_EXEMPT: frozenset[str] = FUNCTION_WORDS | CLAUSE_CONNECTIVES
```

**Both constants are `frozenset[str]`, flat, exactly as `FUNCTION_WORDS` is.** The categories below are a reader's aid written as source comments inside the one literal; they are not a nested structure and nothing flattens anything at runtime. This is pinned rather than described because the union line above is the whole mechanism, and a category grouped tuple would raise `TypeError` on it.

`FUNCTION_WORDS` is unchanged by value and keeps its two readers, `tokens_match` and `sub_claim_is_additive_free`. `COMPLETENESS_EXEMPT` has exactly one reader, `response_is_complete`. A member of `CLAUSE_CONNECTIVES` that is not also in `FUNCTION_WORDS` is therefore exempt from the completeness demand and still a content token to the additive half.

`CLAUSE_CONNECTIVES` is a closed spec constant, enumerated from the AC-21 rule rather than from observed failures, and it is exhaustive over four closed grammatical categories plus the correlative markers. Members already present in `FUNCTION_WORDS` (`and`, `but`, `or`, `nor`, `for`, `so`, `as`, `if`, `that`, `which`, `when`, `because`, `then`) are not repeated here; the union covers them, and the two sets are disjoint by construction.

| Category | Members |
|---|---|
| coordinating conjunctions | `yet` |
| correlative markers | none survive the second exclusion rule |
| subordinating conjunctions | `albeit`, `although`, `lest`, `though`, `unless`, `whereas`, `whether`, `while`, `whilst` |
| conjunctive adverbs | `accordingly`, `additionally`, `also`, `anyway`, `consequently`, `conversely`, `furthermore`, `hence`, `however`, `indeed`, `instead`, `likewise`, `meanwhile`, `moreover`, `namely`, `nevertheless`, `nonetheless`, `otherwise`, `rather`, `regardless`, `subsequently`, `therefore`, `thereby`, `thus` |
| relative and interrogative pro-forms | `how`, `whatever`, `whenever`, `where`, `whereby`, `wherein`, `whereupon`, `wherever`, `whichever`, `who`, `whoever`, `whom`, `whose`, `why` |

Forty eight members. **The correlative row is named and empty, which is a result rather than an oversight.** `both`, `either`, and `neither` each quantify over a set of two, and a quantifier surviving a split intact is exactly why the whole closed word class was rejected, so all three fall to the second exclusion rule. `whether` is the only correlative marker that quantifies nothing, and it sits in the subordinating row under its ordinary use of introducing an alternative or an embedded question. **Several members have a use in more than one row** (`where` heads a relative clause and also subordinates, `while` does both, `whether` is correlative and subordinating). Each is listed once, in the row matching the use that motivates it, and the row carries no runtime meaning. `where` sits in the pro-forms row because that is the use experiment 0012 measured and the one AC-21's argument names.

The three measured tokens sit in three different rows, which is the reason the rule is stated over the function rather than over any one row: `where` is a relative adverb, `while` is a subordinating conjunction, and `instead` is a conjunctive adverb. The count is a property of the enumeration, not a prediction of effect; most members have never been observed failing here and some may never occur, which is what enumerating ahead of the failure costs.

**Two exclusion rules, and the words each one removes.** Both are part of AC-21's membership rule, and both exist because the enumeration is otherwise mechanical and an implementer reading a grammar reference would add these back.

*Primary use is a content word*: `provided`, `given`, `granted`, `considering`, `seeing`. Each has a real subordinating use in English and a far more likely lexical use in this corpus (`the adapter provided the record`), so each stays a content token.

*The second use is truth conditional rather than clause relating*: `once`, `still`, `further`, `finally`, `specifically`, `similarly`, `after`, `before`, `since`, `till`, `until`, `than`, `except`, `besides`, `both`, `either`, `neither`. This is the same test that rejected exempting the whole closed word class, applied to the enumeration itself rather than only to the option. `The check runs once` decomposes into `The check runs`, and no other word in that clause carries the frequency, so `once` does the work a quantifier does rather than the work `where` does. `still` marks continuation, `further`, `specifically`, and `similarly` mark degree and manner, and `finally` marks time. The temporal subordinators `after`, `before`, `since`, `till`, and `until` are also prepositions (`after the migration`), which is the same shape as the `without` and `during` case used to reject the closed class option. `than` carries a comparison, and `except` and `besides` carry an exclusion, which is content in the way a quantifier is. `both`, `either`, and `neither` quantify over a set of two, which is the `all` and `every` case at a fixed size. A word that survives a split intact is not dissolved by decomposition, and exempting it would give up reach the omission guard did not have to give up. `furthermore`, `likewise`, `namely`, `conversely`, `meanwhile`, and `subsequently` stay in, because they have no second use: their only job is relating one span of discourse to another.

**One exclusion has a named cost, and it is the sharpest case in either list.** `both`, `either`, and `neither` are genuinely dual, and their two uses point opposite ways. The correlative use really is dissolved by decomposition: `the pipeline uses both BM25 and Chroma` splits into two sub claims that each name one retriever, and neither has anything left for `both` to do, so excluding it means that sentence can fail completeness on `both` and be dropped. The quantifier use really does carry content: `both options were rejected` loses the count and the exhaustiveness if `both` goes missing. The exclusion takes the second reading because the spec's stated safe direction for this set is to err toward dropping a sentence, and because a spurious drop is visible while a permitted omission is not. **It is expected to cost live drops, and the instrument is already pointed at it**: if `both` shows up as a `failure_token` in the task 19 re measurement, that is this exclusion being paid for, and it is the one member of either list worth revisiting on evidence rather than on the rule.

**The two rules are what make the enumeration checkable rather than a list.** A reader who disagrees with a member should be able to name which rule it fails, and a reader who wants to add one should have to say which category it joins and which rule it survives. The first pass of this enumeration failed its own second rule on six members, which is the argument for writing both rules down beside the table rather than only the categories.

Matching against this set is exact token membership after AC-11 normalization, never a stem or base set lookup, exactly as `FUNCTION_WORDS` is matched. So `whose` being exempt says nothing about any other token, and no inflection of an excluded word is reached by accident.

A response containing a genuinely new content word fails as `not_additive`. A response that leaves a parent content token unmatched fails as `incomplete`. Either failure drops the parent sentence and records one `rejected_decompositions` row plus one `decomposition_invalid` row in `dropped_sentences`. Rejected claim text is never recorded.

**The subsumption relation and the polarity set** (AC-22). This runs on a response that already passed both AC-11 halves, so it is not a validity check and it produces no disposition. It answers one question per sub claim: is this claim a strict lexical weakening of a sibling, such that verifying the sibling covers every content word this one names.

```text
content token here = a token outside FUNCTION_WORDS
                     (never COMPLETENESS_EXEMPT; a clause connective is
                      content to this relation)

subsumes(sibling, candidate) is true when all three hold:

  1. strict content subset
     every content token of candidate matches a distinct content token of
     sibling through tokens_match, walking greedy first unused in sibling
     order, and sibling carries at least one content token left over
     -> this walk records the assignment; conditions 1 and 3 are one
        traversal, and condition 3 never recomputes a matching

  2. matching polarity and modality
     { t for t in candidate tokens if t in POLARITY_MARKERS }
       ==
     { t for t in sibling tokens  if t in POLARITY_MARKERS }

  3. order preserving
     the sibling positions recorded by rule 1 are strictly increasing

then, over the whole response, in two passes:

  pass 1  maximal = { c : no sibling subsumes c }
          maximal is never empty, because subsumption is strict and the
          response is finite, so the ordering cannot cycle

  pass 2  prune c when some m in maximal subsumes c
          subsumed_by = the first such m in provider order
          a candidate subsumed only by a non maximal claim is NOT pruned
```

`POLARITY_MARKERS` is **derived from `FUNCTION_WORDS`, not written beside it**, so the two cannot drift apart and a test can assert the subset relation by value:

```python
POLARITY_MARKERS = FUNCTION_WORDS & frozenset(
    {
        # negators
        "not", "no", "never", "nor",
        # modals
        "can", "could", "will", "would", "shall", "should",
        "may", "might", "must",
    }
)
```

All thirteen are already `FUNCTION_WORDS` members, so the intersection is the full literal today and the intersection form is what keeps that true if either list ever moves. **Polarity markers stay function words everywhere else.** They are not content tokens, they are not demanded by completeness, and they are not budgeted differently by the additive half. This set is read by the subsumption relation and by nothing else, which is the same containment rule AC-21 put on `COMPLETENESS_EXEMPT`.

The relation is a pure function in `verification.py` and is called from `query.py` between the AC-11 verdict and the entailment loop. It is deliberately **not** folded into `classify_decomposition_detail`: that function answers whether the response is a faithful division of the parent, and pruning is not that question. Folding it in would make a disposition depend on a rule that has nothing to do with validity, and would put a fourth traversal inside the one place AC-20 insisted on keeping to a single traversal and a single verdict.

A pruned claim keeps its `decomposed` row, its position, and its text, with `entailment="pruned"` and `subsumed_by` naming the first maximal sibling in provider order that subsumes it. Contiguous sub claim ids (AC-6) are therefore unaffected: nothing is removed from the response, only from the set of claims entailment is asked about. Containment still runs on it, so `contained` and its citations are truthful; only the entailment call is skipped.

**The two pass shape is the whole safety argument and is not an optimisation.** A one pass rule that let any subsuming sibling qualify would let `subsumed_by` point at a claim that is itself pruned, and the criterion's guarantee would then rest on `tokens_match` composing transitively across a chain. It does not generally: a base set intersection can relate A to B and B to C without relating A to C. Two passes remove the need to reason about that at all, for the cost of one filter over a list that never exceeds `MAX_SUB_CLAIMS`.

Coverage receives the original question, the canonical facets in facet order, and the emitted sentences in output order. It uses `MODEL_FACETS_AND_ANSWER`, temperature 0, and the existing single schema repair attempt. Its response schema remains one row per facet with `facet_id`, `covered`, nonempty `reason`, and `sentence_ids`. Supporting ids are unique and follow emitted sentence order.

`COVERAGE_SYSTEM_PROMPT` gains one sentence for AC-16, the caveat exclusion the observed miss walked through. The rest is unchanged, and the new sentence sits with the exclusion list it belongs to:

```text
For each facet, decide whether one provided answer sentence directly states
its answer. Judge only what that sentence says. Do not combine sentences. A
reason, context, consequence, premise, or anaphoric fragment does not state a
decision. A statement about what the evidence does or does not establish is a
limitation, not a decision, and never covers a decision facet. One sentence
may support several facets only when it directly answers each one.
```

**Schema property descriptions** (AC-17). One exists, on the coverage schema's `sentence_ids` property, and it is recorded here as a constant for the same reason the prompts are: it is text sent to the model, and the rule it restates is stated in more than one place and has to stay in step. (An earlier draft said three places and named directness as one of them; see the correction in AC-17. This description restates a shape rule, not directness.) Its validator is `validate_coverage`, which rejects an uncovered row that names sentences whatever the description says:

```text
Sentence ids that directly state this facet's answer, in the order the
sentences were given. Leave this empty when covered is false: never name a
sentence you judged and rejected.
```

No other property carries a description, and one may only be added under the AC-17 bounds. The AC-16 caveat exclusion is deliberately not one of them: no validator enforces it, so it belongs in the instruction above and nowhere else.

**Key invariants**:
- Nothing the model is shown as a label may be a token prose cannot contain. A chunk id is stripped because it cannot be reproduced; a field label is rendered in plain words so it never needs stripping. The rule behind both: any string put in front of generation is a string that can come back inside a draft sentence, and a sentence carrying a token no decomposition can reproduce is dropped unconditionally.
- Only a closed vocabulary this project produces reaches the prompt as authority. `value_path` qualifies, since the chunker writes it. `record_title` does not, since the adapter reads it out of the corpus, and the evidence block that would carry it is fenced to the model as untrusted.
- The label says which part of the record a chunk is. It never says what the chunk means, and it is never evidence in its own right; grounding still reads the chunk text alone.
- Directness lives in AC-12 and `COVERAGE_SYSTEM_PROMPT`, and is enforced nowhere. `validate_coverage` enforces shape only. Two unenforced statements of one rule have to be changed together.
- An instrument added to a measurement run must change no decision the pipeline makes. The additive failure category records why a check stopped; the disposition, the retry set, and the drop are all unchanged, which is what lets it ship in the same task as a change to model input.
- A gate verdict never attributes a result. The answering half fails both when no sentence survives and when coverage refuses a good one, so any claim about which of those happened is read from the trace, never from pass or fail.
- A semantic measure is labelled as one. The count of sentences that state the decision is a reader's judgement, so its rule is written before the runs and every sentence it judged is quoted, which is the closest such a measure gets to reproducible.
- A chunk id never appears in `DraftSentence.text`. Citations travel in `chunk_ids` only, and the strip runs at the generation boundary, so no rule downstream has to know that a chunk id is not a word. Every later consumer of `text` (the containment shortcut, the token matcher, the rendered answer) inherits the guarantee instead of re deriving it.
- A gate never reads the document that defines it. The self corpus fixture excludes this spec, and the gate's expected answers live in the fixture manifest outside `docs/specs/`, so no spec can become a source for the answer its own gate checks.
- A gate expectation is data in that manifest, never a literal in code and never prose in a spec. The loader reads every key and refuses one it does not recognize, so a manifest written before an oracle was strengthened cannot run the gate under the old weaker oracle.
- An answering gate names the value path its answer must cite, not only the record, and the citation must belong to the sentence that does the covering. A record wide check cannot tell a decision from a caveat drawn from the same record, which is how a wrong answer passed once already; a whole answer check cannot tell it once a second sentence is emitted.
- An abstaining gate names the cause it expects. Abstaining because every sentence was dropped is a different event from abstaining on an uncovered facet, and only one of them is the behaviour being checked.
- A gate assertion is never satisfied vacuously. A cause read over an empty coverage tuple, a miss count over zero covered facets, and a prefix no chunk in the corpus carries are each a state the gate reports as not measured, never as met.
- A schema property description restates a rule some validator already enforces, and is never the only statement of a rule. Deleting every description must leave every test outcome unchanged.
- The accepted context lookup is the only source of provider evidence and output chunk citations. Missing ids remain trace only.
- A sub claim is never emitted. Only whole parent sentences enter coverage or public output; sub claims decide which parents survive.
- A parent sentence is emitted only when its decomposition is valid and every sub claim is supported. Either failure drops the parent whole. There is no partial sentence.
- The additive half is measured per sub claim against a fresh parent pool; the completeness half is measured across the whole response by presence. Applying either scope to the other half is a defect: response wide consumption rejects a correct split that restates its subject, and per sub claim completeness rejects every split of more than one clause.
- The lexical test proves only that the sub claims neither add content to the parent nor omit content from it, under its token rules. It does not prove factual equivalence or relation preservation. A decomposition that preserves every content token while inverting the meaning passes it; entailment is the only check that can catch that.
- A sub claim is never removed from a response. Removing one would break the completeness half by construction, so validity is a property of the whole response, never of an individual sub claim.
- Decomposition runs only after whole sentence containment fails against available evidence. No available evidence removes the sentence without a provider call.
- Grounded is `contained or entailment == "supported"`, the existing binary verdict. There is no separate acceptance threshold.
- Grounding decides whether a sentence is supported. Coverage separately decides whether that one sentence directly answers a required facet.
- Coverage uses the canonical facet tuple unchanged. Exactly one valid row per facet is required in the same order. A covered row names one or more unique known emitted sentence ids. An uncovered row names none.
- Coverage cannot combine sentences. One sentence may appear in several rows only when it directly answers every named facet.
- Query 4 diagnosis reads `GenerationTrace.facets`, coverage rows, uncovered facets, and result state in that order. A merged decision and reason facet is assigned to facet extraction before coverage is judged. Separate facets make coverage directness independently diagnosable.
- Provider schema failure receives one repair attempt. Final decomposition or coverage failure fails the query at `claim_verification`; it never becomes abstention.
- `schema_version` stays 2. The runtime reads no persisted query result, and all five trace additions are output only.

**Security model**:

No new surface. Decomposition sends the candidate sentence and available cited chunk text to the existing provider, the same class of data entailment already sends. Rejected claim text is not added to the trace or normal output.

**Configuration required**:

None. Decomposition and entailment stay fixed to `gpt-4o-mini`. Coverage uses `MODEL_FACETS_AND_ANSWER`. All calls use temperature 0. There is no acceptance threshold to configure. The cap, lexical matcher, prompt text, schemas, and dispositions are spec constants, not settings.

**Critical test scenarios**:
- Fabrication removal: a fused sentence returns both grounded and fabricated sub claims; the fabricated one is unsupported, so the whole parent is dropped and the grounded clause does not survive on its own, verifies **AC-1**, **AC-4**
- Omission attack: decomposition returns only the grounded clause and omits the fabricated one; the response fails the completeness half, so the parent is dropped as `incomplete` with no entailment call, verifies **AC-1**, **AC-11**
- Whole sentence output: a sentence whose decomposition is valid and fully supported is emitted verbatim, with its own sentence id and its parent citations, in draft order among the other emitted sentences; no sub claim text appears in output, verifies **AC-4**
- Accepted context boundary: missing citations are removed before whole containment; a sentence that proceeds on its available ids still records its `missing_chunk_refs` row; no output citation names a missing id, verifies **AC-8**
- Citation precision: an emitted sentence cites its parent's available ids deduplicated in parent order, while sub claim level containment and entailment citations stay in the trace, verifies **AC-4**, **AC-8**
- Decomposition outcomes: valid, actual empty, over cap, normalized duplicate, `not_additive`, and `incomplete` remain distinct in trace; the whole response checks fire in their stated order before the two half test; every invalid response writes exactly one `rejected_decompositions` row and one paired `decomposition_invalid` row, verifies **AC-6**, **AC-10**, **AC-11**
- One drop reason per sentence: a sentence with no available citations, an invalid decomposition, and an unsupported sub claim each produce exactly one `dropped_sentences` row with the right closed reason, and no sentence produces two, verifies **AC-6**
- Lexical limits, additive direction: `refetch` and `refetches` match, `use` and `using` match under the dropped `e` rule, `add` and `adding` match under the plain suffix rule, `ship` and `shipped` match under the repeated final character rule, `rely` and `relies` match under the `y` to `i` rule, a two character token matches itself exactly but never inflects, two added function word tokens pass while a third fails, an unlisted function like word is treated as content and fails, and a new content token fails the response as `not_additive`, verifies **AC-11**
- Additive scope: the experiment 0002 decomposition, three sub claims each restating `The hybrid retrieval system` against a parent naming it once, passes because the pool resets per sub claim. The same input fails if a build consumes response wide, so this test pins the scope and guards the exact regression the cross check caught, verifies **AC-11**
- Lexical limits, completeness direction: a decomposition covering every distinct parent content token passes; one dropping a content bearing clause fails as `incomplete`; a parent token repeated three times is satisfied by one occurrence in one sub claim (presence, not multiset); parent function words need no match; a response that splits one parent clause across two sub claims still passes, verifies **AC-11**
- Check ordering and retry: a malformed empty text row fails as `provider.decompose` before duplicate normalization could pair two empty strings; empty, over cap, and duplicate fire in their stated order ahead of the two half test; a two half failure triggers exactly one retry, and a second invalid response drops the parent, verifies **AC-6**, **AC-7**, **AC-11**
- Tie break determinism: a sub claim token eligible against two parent tokens takes the first unused one in parent order, and the same input always reaches the same verdict, verifies **AC-11**
- Semantic limits: a decomposition that preserves every content token while dropping `not`, reversing actors, or reordering relations passes the lexical test, documenting that the check makes no semantic guarantee and that entailment is the only defence, verifies **AC-11**
- Marker strip at the generation boundary: a draft sentence carrying a bracketed multi id group, one carrying a bare `ch_` id mid sentence, and one carrying a trailing group all reach `DraftSentence.text` with no chunk id and single spaced prose; `chunk_ids` is unchanged in each; a sentence whose text is only a marker fails as empty text rather than reaching output; and a sentence that was one sentence only because a marker followed its period is judged on the cleaned text, verifies **AC-13**
- Marker regex edge cases: an uppercase hash is stripped under the case insensitive rule; `ch_` followed by 63 or 65 hex characters is left alone, since it is not an id and the word boundary stops a 64 character prefix match; a comma separator with no surrounding space and one with spaces both parse inside a group; and a mixed group such as `[see ch_<64 hex>]` loses only the bare marker and keeps its brackets and its prose, verifies **AC-13**
- Whitespace repair after the strip: a trailing group before a full stop leaves no space before it, a mid sentence group leaves no space before the following comma, an existing parenthetical with no marker in it is untouched, and a sentence with no marker at all is returned unchanged. These pin the readable prose AC-4 emits verbatim, verifies **AC-4**, **AC-13**
- Duplicate collision from the strip: two draft sentences with identical prose and different markers become identical after stripping and fail the response as a duplicate, which is the intended reading rather than an accident; a deterministic test pins it so the behaviour is chosen rather than discovered, verifies **AC-13**
- Marker strip restores the cost bound: a sentence that is verbatim in its cited chunk **except** for an inline marker takes the containment shortcut after the strip and pays no decomposition call, the case that made AC-5 silently dead, verifies **AC-5**, **AC-13**
- Field label mapping: every path in the pinned nine entry tuple renders a nonempty label; an indexed path renders the same label whatever its index, so `why[0]` and `why[3]` match; an unmapped path renders nothing and its block carries no `Field:` line; and the rendered block matches the pinned AC-18 shape with the chunk id still in parentheses, verifies **AC-18**
- Label safety, the property the plain words choice buys: a draft sentence that echoes a rendered label whole still decomposes and survives, because every token of the label is ordinary vocabulary. The same test run against the dotted `value_path` fails the completeness half, which pins why the mapping exists rather than leaving it as an assertion, verifies **AC-18**
- Record title never reaches the prompt: the generation evidence for a chunk whose record has a distinctive title contains the id, the label, and the text, and does not contain the title, verifies **AC-18**
- Additive failure category: a sub claim whose first failing token is an unmatched content token records `content_token`; one whose first failing token is the function word past the bound records `function_word_overrun`; a sub claim carrying both records whichever token comes first in token order, which pins the early return reading against a full scan; an `over_cap`, `duplicate`, or `incomplete` response records the empty category; and the category comes from the first failing sub claim. The disposition stays `not_additive`, the retry still fires, and the drop is unchanged, so the field is observational, verifies **AC-19**

- Provider failure: malformed decomposition or coverage gets one repair, then fails with the correct provider code at `claim_verification`, verifies **AC-7**, **AC-12**

- Multi clause coverage: a single emitted sentence stating a three part decision covers its facet, the case experiment 0002 recorded as wrongly abstaining under the fragment contract, verifies **AC-4**, **AC-12**
- Coverage row integrity: unknown, missing, duplicate, or out of order facet ids and invalid sentence ids fail validation, verifies **AC-12**
- Directness table: a stated decision covers a decision facet; a reason, premise, consequence, unrelated sentence, cross sentence combination, or anaphoric fragment does not; one compound sentence may cover several facets only when it states each answer, verifies **AC-4**, **AC-12**
- Diagnostic split: a merged query 4 facet reports `facet_extraction`; separate facets with a wrongly covered decision report `coverage_directness`; an uncovered decision with an answered result reports `query_state`, verifies **AC-2**, **AC-12**
- Abstention surface: sub claim and dropped sentence rows remain in trace, but public sentences and citations are empty, verifies **AC-4**, **AC-12**
- Directness on whole sentences: the directness table cases are re-run against emitted parent sentences rather than fragments, confirming a compound sentence covers several facets only when it states each answer, verifies **AC-4**, **AC-12**
- Self corpus gate: against the frozen fixture of this repository's own specs with this spec held out, the paired decision query answers from its source record with a whole sentence and the paired reason query keeps abstaining. The queries and their expected records live in the fixture manifest, not here, so this spec cannot become a source for its own gate's answer. The cheap gate that falsified the previous build, verifies **AC-4**, **AC-12**, **AC-14**

## Consequences

**Positive**:
- A fragment too atomic to be grounded stops taking a correct sentence down with it. `The decision was made.` cannot be supported by any evidence, and the three siblings that state the same thing with its object attached all can, so the sentence's fate is decided by the claims that assert something. This is the first criterion in the spec that reaches decomposition granularity at all; every previous one judged whether the split was faithful, never whether a piece of it was checkable.
- The skip is free in the direction that matters. A prune is only permission to skip a check, so refusing to prune costs exactly today's behaviour, which is why three conditions could be stacked on the relation without weighing each one against a capability loss. No other guard in this spec has that property, and it is why this is the cheapest safety argument the chain has had to make.
- The prune rate becomes measurable. It was unmeasurable by construction before, since a claim never sent to entailment left no trace, and the new row carries the claim, its position, and the sibling that covered it.
- The abstention gates stop being satisfiable by wholesale rejection. Query 4 and query 5 have both passed on state alone since experiment 0002, and the deferred list has flagged that as possibly flattering them since then; pinning a cause on both at once means the answer gets learned rather than chosen.
- The measurement policy separates two variances instead of averaging them. Experiment 0013's own table already distinguished a store effect from a provider effect, and naming the denominator rule turns that reading into something the next experiment has to do rather than something one experiment happened to notice.
- The completeness half stops demanding a match for the words decomposition is instructed to dissolve. `DECOMPOSE_SYSTEM_PROMPT` asks for standalone atomic sub claims, which is precisely what removes a clause joining word, so the check and the prompt stop contradicting each other on this class. Three of the five failing live fixtures have their blocking token removed at once.
- The two halves of AC-11 can now move independently. Every previous amendment had to argue its way through the safety critical half because both read one matcher and one set; this one touches a set only the completeness half reads, so the guard behind AC-2 provably does not move. That separation is reusable: the next completeness finding no longer has to be weighed against the fabrication guard.
- The membership question is answered once rather than per token. Four experiments each spent a live batch to learn one word. A rule enumerated from four closed grammatical categories closes `whose`, `although`, `however`, and fifty nine others without a fifth batch, and the arbitrary boundaries in the current set (`which` exempt but `whose` not, `when` exempt but `while` not) go with it.
- The additive half stops rejecting the transformation it exists to check. Turning a subordinate clause into a standalone sub claim changes a participle into a finite verb, and the base set matches across that change while still refusing a substituted word, so a correct decomposition of a clausal sentence is no longer destroyed by a verb ending. Both halves share `tokens_match`, so the completeness half gains the same reach.
- The fused clause fabrication can no longer hide inside a sentence; query 4 and query 5 can abstain honestly.
- The verification unit now matches the attack surface, atomic claims instead of whole sentences.
- Cost is bounded: only non verbatim sentences pay the decomposition call.
- The trace shows the split itself, so a bad split is visible, and the empty, dropped, and missing signals point at upstream problems.
- Answers read as prose again. The output is the drafted sentence, so the orphaned references and exploded lists that experiment 0001 recorded cannot occur.
- A decision that takes several clauses to state can be answered. Experiment 0002 showed the fragment contract made such decisions unanswerable, since coverage may not combine sentences and no fragment stated the whole decision.
- Coverage becomes reliable in both directions from one change. A vacuous fragment can no longer cover a facet, because fragments are never emitted; and an informative sentence is no longer split into pieces that individually cover nothing.
- The lexical test has one job and one shape, so the granularity argument that consumed two build cycles cannot recur. A removed sub claim breaks completeness by construction, so per sub claim dropping is not a coherent option to relitigate.
- The additive tolerance is now safe to loosen, because a sub claim never reaches output; its only job is to stop substitution. Calibration stops being a safety question and becomes a measurement.
- The answered state again means every fixed facet has a direct answer. Grounded partial material cannot silently stand in for a missing decision.
- Missing citations can never escape the accepted context boundary into output.
- AC-5 is live again. The containment shortcut was unreachable for every marker bearing sentence, so the cost bound the spec claimed was not being paid; roughly half the sentences were paying a decomposition call the spec said they should not.
- The marker fix lands where the artifact enters the system, so every later consumer of `text` inherits it. The emitted answer also stops showing raw chunk ids to the reader, which nothing had noticed as a separate output defect.
- The self corpus gate becomes a fixture with a held constant input, so a changed gate result can be attributed to the code. Against the live tree it could not: editing any spec changes the gate's evidence, and the gate tests code and corpus content at once.
- The gate can now fail a wrong answer. State plus record id passed a caveat drawn from the right record; state plus a co located `decision.chosen` citation does not, and the caveat that caused the false pass was not one of the 6 `decision.chosen` chunks in the 244 chunk fixture store.
- An abstention gate can now tell an honest abstention from a collapse. That distinction is the one every experiment since 0002 has had to make by hand while reading traces, and the gates could not make it at all.
- The oracle is reused rather than reinvented. The co location rule, the per fixture rate reporting across `--runs N`, and the report shape all exist and are already hardened in review; the gate adds two optional oracle fields and a loader on top of them, and changes nothing the JobPilot battery runs through.
- Every new assertion has a not measured state instead of a silent pass. The empty coverage tuple, the zero denominator miss count, and the unsatisfiable prefix each report that the gate could not judge, which is the failure mode this whole criterion was written to remove.
- The gate's expectations still live only in the fixture manifest, and now the code reads them from there instead of a person transcribing them into a script. The AC-14 property that no spec can be a source for its own gate's answer is preserved by construction.
- The AC-16 miss count comes free with the AC-15 oracle, so the question of whether coverage keeps accepting caveats gets an answer from runs that were happening anyway.
- The fix uses a signal the pipeline already had. Nothing is inferred, retrieved, or asked of a model: the chunker writes `value_path`, retrieval carries it, and generation was the only stage throwing it away. The embedding side has rendered the same information above the same text since spec 0007.
- Coverage is not touched, so the caveat hole AC-16 closed stays closed. Experiment 0006 showed removing that exclusion brings the OD-5 defect straight back, so the stage that is behaving correctly is left alone and the stage feeding it wrongly is the one changed.
- Answers stop describing and start answering. A reader asking what was decided gets the decision, which is what the corpus stores; the previous output described the system and left the reader to infer that a decision had been made.
- The label failure class does not exist rather than being caught. Plain words cannot produce an unmatchable token, so there is no second strip, no second regex, and no ongoing obligation to track the value path grammar as the schema grows.
- A wrong claim in this spec is corrected in place. AC-17 said directness lives in three places and that one enforces it; both halves were wrong, and the correction stands where the claim was rather than in a new spec, matching how this project handles a correction.
- Task 13 gets an instrument before it needs one. The `not_additive` split has never been measurable, and the runs that measure this fix produce it at no extra provider cost.

**Negative / tradeoffs**:
- **A non maximal sub claim's argument binding is never checked.** This is AC-22's residual and it is a fabrication side residual, which every previous widening in this spec was not: the first two loosened the omission half. Three conditions narrow it, none closes it, and no lexical relation can, because deciding it means deciding predicate argument structure. What bounds it is that a maximal claim can never be pruned, so a fabricated content word cannot leave the verification set, only be rebound. That bound is an argument, not a measurement, and the boundary case is pinned as a test so a later reader can attack the argument on a concrete sentence.
- The verification path gains a third lexical rule family, after the matcher and the exemption set. Each was introduced for a measured reason and each is separately testable, but the number of ways a sub claim can be treated specially is now four (function word, exempt connective, polarity marker, subsumed), and a fifth should be a harder sell than the fourth was.
- Two of the spec's abstention gates are deliberately turned red, and AC-2 has been the one green criterion in the chain since experiment 0008. The record will show the feature going backwards on paper in the round that looked hardest at whether it was ever forwards.
- The decision grade denominator doubles the live cost of any measurement that settles something, from roughly four minutes to roughly sixteen, and two tasks in this round each pay it. The alternative was reading criteria off numbers that experiment 0013 showed disagreeing with themselves across two batches of identical code.
- The store level variance is named and not fixed in this round. A suspected correctness defect sitting in Follow-up while measurements continue against it is a real carried risk, and the reason it is carried is that folding it into a run count would have hidden it.
- **The amendment widens the completeness half as well as the additive half**, because both match through `tokens_match`, and completeness is the safety critical direction that catches the AC-1 omission attack. A broader matcher passes completeness more often. The attack is measured to still fail, including on cases built to exploit the widening, but the residual class named in AC-1 (an omitted clause whose every content word is an inflection of a surviving word) is genuinely reachable now and was not before.
- The base set is broader than what shipped, so the additive guard is measurably looser than the guard AC-2 passed 6 of 6 under. The measurement says it adds no false match on 3,690 tokens of this project's own prose, which is evidence and not a proof; a corpus with different vocabulary could hold a pair these five rules join wrongly. The live batches in task 18 are what confirm AC-2 still holds, and AC-2 is the criterion to watch if anything regresses.
- Computing a base set per token costs more than the old pairwise comparison, and the additive half runs it inside a greedy walk over the parent pool. Memoizing per token keeps it bounded, but it is a real cost the directional form did not have.
- Two more defaulted fields land on `RejectedDecomposition`, and `response_is_complete` changes its return type for the second time in this spec's life. Both are observational, and both widen the trace shape that spec 0011 and feature 15 will render.
- **The omission guard loses reach, for the second time in two days, and this time by removing tokens from the demand rather than by widening what counts as a match.** A clause carrying no lexical verb, noun, or adjective can now be omitted without failing completeness, and such a clause can still assert something: the copulas and negators are already exempt, so `although it was not` is a real assertion built entirely from exempt words. The class is enlarged rather than created, and the honest bound is that a fabricated decision names an entity, an action, or a property, and every word that does so is still demanded. It is a real loosening of the safety critical direction, taken on evidence about the other direction's cost, and task 19 carries a constructed test at the boundary rather than an argument.
- **The trace loses its last signal that a connective was ever there.** Before this, the completeness half could not verify that a clause relation was preserved, which was always entailment's job, but it did require the word to appear somewhere in the response, so a reader of a `rejected_decompositions` row could at least see it. After AC-21 a connective can vanish from a decomposition with nothing recording that it did. This is not a new safety hole, since entailment is the acknowledged backstop for relations, and it does mean the follow-up watching for label bleed and the next completeness finding both have one less thing to read.
- **Forty eight words is a large edit to justify from three observations.** The rule is enumerated from grammar, so most members have never been seen failing here and some never will. That is the deliberate trade against growth by failure, and it means the set's size is not evidence of anything: it is a count of the enumeration, not a measured effect.
- **The two halves now read two vocabularies, and a reader has to know which.** Before this, one set answered every question about function words. Now `FUNCTION_WORDS` answers the additive question and `COMPLETENESS_EXEMPT` answers the completeness one, and the same word can be a function word to one half and a content token to the other. `while` is exactly that. The naming and the single reader per set bound the confusion; they do not remove it, and a future edit to the wrong constant would be silent in one direction.
- **A sub claim that introduces a connective now fails as `content_token`**, which reads oddly in the AC-19 split since the word is plainly a function word by any grammar. It is the correct verdict under the decision to keep the halves separate, and it will make the `additive_failure` distribution slightly harder to read if it ever fires. It is expected not to, since decomposition pulls clauses apart rather than joining them, and `failure_token` is what would show otherwise.
- **The rule has one non mechanical step.** The primary use exclusion (`provided`, `given`, `granted`, `considering`, `seeing`) is a judgement about what this corpus is likely to contain, not something a grammar reference settles. It is written down and the five words are named, so the judgement is auditable rather than implicit, but a sixth such word would need the same call made again.
- **This does not predict that the three fixtures pass.** A first cause is not the set of causes, and `falls` gave way to `where` under exactly this reasoning one experiment ago. Task 19 may well move the token again rather than clear the abstention, and the plan should expect that rather than treat it as a failure.
- Task 13's calibration target moves for the third time. The additive tolerance was already measured to reach 0 of 18 drops, and this amendment changes the distribution underneath it again, so the figure it calibrates against has to be re read after task 18 rather than carried forward.
- The frozen fixture goes stale by design. It stops reflecting the current specs the moment a spec changes, and re baselining it is a deliberate step someone has to take. That is the cost of a held constant input, and the manifest hashes make the drift visible rather than silent.
- The fixture duplicates spec content inside the repository. It is a copy of decision records living beside the real ones, which is exactly the second source this project warns about elsewhere. It is mitigated, not eliminated, by keeping it outside `docs/specs/` (so no tool reads it as a record) and by the manifest naming its source commit.
- The marker strip is a repair on the boundary, not a guarantee about the model. If the model finds a new way to write an id, the strip's fixed shape does not cover it. The shape is pinned to what `chunk_id` produces and matched case insensitively, so this is bounded, but it is still a pattern match on model output.
- The strip makes an existing failure path reachable more often. Two draft sentences whose prose is identical and whose markers differ now collide and fail the whole response as a duplicate. The rule is unchanged and the reading is deliberate, but the rate is not: before AC-13 those sentences were distinct strings and both survived.
- The fixture is not a byte faithful stand in for the live corpus, only a chunk faithful one. Its records resolve no code paths, so their `evidence` sets are smaller and their `mentions_unresolved` counts higher than a live adaptation produces. Task 11 verifies the chunks match and the gate reads only those, so the divergence is confined rather than removed.
- One more provider call per non verbatim sentence adds latency and cost to those queries; a sentence that decomposes into K sub claims that all fail containment can add up to K further entailment calls on top.
- The decomposition model can split poorly, which can keep a fabricated fragment that separately passes verification or drop grounded content; the trace makes both visible but does not fix them.
- Under splitting is a known, unresolved risk: if the decomposition returns the whole sentence as a single sub claim, that sub claim's entailment check degrades to today's failing whole sentence check for that sentence. This feature makes the sub claim count visible in the trace so an under split is observable, it does not guarantee against it.
- **One bad clause now costs a whole sentence.** A sentence whose sub claims are all supported but one loses every grounded clause it carried, not just the offending one. This is the deliberate trade for whole sentence output, and it will raise the abstention rate.
- **The lexical tolerance now drives the abstention rate**, because an unverifiable sub claim and an unsupported one have the same effect on the parent. A harmless rephrase the stem rules do not cover drops a good sentence. Experiment 0002's `S1.4` is exactly this case, and it means the revised build does not automatically pass that query; task 13 exists to calibrate it. The difference from the earlier drafts is that mis-calibration now produces a plain abstention, which the harness measures, rather than strange output nobody can reason about.
- The lexical test cannot prove preserved actors, negation, scope, order, or relations. Entailment remains responsible for factual support.
- Completeness is measured on content tokens, so a decomposition that keeps every content word but inverts the parent's meaning (a dropped negation, a reversed relation) passes the lexical test. Entailment is the only thing standing between that and output, which is a real limit of a deterministic check.
- The 6 of 6 acceptance gate is strong evidence, not a measured abstention rate; a true rate needs more runs.
- Coverage uses the larger fixed generation model, so every nonempty query costs more than the earlier coverage call.
- Strict complete coverage can abstain even when some emitted sentences are useful. A future partial answer surface would need to say which facets remain unanswered instead of calling the result complete.
- `evaluate` grows a way to load its battery from a file, which is real CLI surface plus a loader that can itself be wrong. The loud failure on any unrecognized key or unsatisfiable expectation is the mitigation, and it is deliberately the annoying direction: a manifest and a build that disagree stop the run rather than quietly weakening the gate.
- The manifest battery's oracle is no longer identical to the JobPilot one. Two optional fields separate them, so a reader now has to know which battery a fixture came from to know what its value path check meant. The alternative was changing the semantics under the eight live fixtures to keep one shape, which trades a documented difference for an undocumented regression risk.
- The AC-16 miss count cannot be read until the answering half starts landing. Recording the denominator keeps that visible rather than letting a structural zero read as a clean result, but it does mean the trigger sits dormant through the calibration work rather than informing it.
- A provisional bar is a bar with a date on it. If nobody returns to the answering half after calibration, the spec carries a number nobody has confirmed. Task 15 records the measured figure so the confirmation has something to read, but the return trip is still a person's job.
- Requiring a `decision.chosen` citation can fail a genuinely good answer that states the decision while citing a rationale chunk instead. That is the deliberate direction: it shows up as a gate failure to look at rather than as a silent pass, which is the trade this whole criterion is making.
- The directness rule now has three copies (AC-12, `validate_coverage`, and the coverage instruction) and only one of them enforces anything. Pinning the text limits the drift; it does not remove the obligation to change all three together.
- The AC-16 trigger commits to building a deterministic guard on 2 misses in 6, which is a small sample. It is a floor for acting rather than a measured rate, chosen because an unnumbered trigger is the undocumented judgment call AC-9 was rewritten to remove.
- **Prose labels read as content, so they may bleed into sentences more readily than a dotted token would, and a bleed is not free.** The words of a leaked label are ordinary content tokens (`decision`, `record`, and `chose` are all outside the closed function word set), so they enter `parent_tokens` like any other content. If the decomposition treats the leaked phrase as scaffolding rather than a fact and leaves it out, the response fails the completeness half as `incomplete` and the whole parent sentence is dropped. That is the same outcome as a leaked chunk id, reached by the same mechanism. What the plain words rendering buys is **probability, not immunity**: an opaque 64 hex token is one a decomposition essentially never reproduces, while ordinary words are ones it usually does, especially under a prompt that already tells it to cover every clause. So the risk drops sharply and does not disappear, and the prompt prohibition against copying the `Field:` line is soft with nothing enforcing it. The Follow-up item that watches for bleed watches the `incomplete` disposition specifically, not just untidy prose.
- **Decision framing can fail entailment where description did not.** An instruction to state a decision pushes generation toward assertive phrasing, and a hedged source chunk (`we chose X, pending further validation`) can be overclaimed into an unhedged decision statement that comes back `unsupported` and drops its parent. This is the mirror of the `not_additive` risk and just as speculative; experiment 0007 records the entailment verdicts so the next decision about it is taken on a measurement.
- The mapping is a second place the record shape is written down, and it has to track `chunking.py`. A pinned tuple, a coverage test, and a named review owner bound the drift; none of them makes the two one source. A tenth `add()` call with no mapping entry degrades quietly to no label, which is safe and silent, and silent is the half worth watching.
- This changes generation, which changes the draft sentences every downstream measurement is taken over. The 68 percent calibration target, the drop cause mix, and the abstention rates were all read from the previous phrasing, and this task moves that phrasing deliberately. Everything measured before task 17 is a reading of a different distribution, which is why task 13 now starts by re reading rather than by calibrating.
- Decision framing may make sentences longer and more clausal, which could raise `not_additive` rather than lower it. That is a plausible mechanism, not a measurement, and experiment 0007 is where it stops being a guess.
- The prompt keeps a line that is inaccurate about its own evidence, on purpose. Ids are described as bracketed and rendered in parentheses, and the task that rewrites that block is instructed not to fix it. A held constant input is worth an inaccurate sentence for one measurement; carrying it further is not, which is why it is scheduled rather than filed.
- The answering half of the gate still has no proof it can pass. This removes the cause experiment 0006 isolated; it does not establish that removing it is sufficient, and the AC-15 answering bar stays provisional until a run meets it.
- The reader half of experiment 0007 is a judgement, and pre registering the rule and quoting the sentences bounds it without removing it. Two readers can still disagree, and the answering bar leans on that number.

**Neutral**:
- `schema_version` stays 2; the five trace fields are additive and query results are not read back from persistence.
- No store change, no rebuild, no new configuration.
- Query 2 citation completeness remains out of scope. Fixed facet coverage cannot demand an omitted record that no facet names.
- No trace field is added for either new assertion. The citation co location check reads citations, and the abstention cause reads the coverage rows that already exist.
- The JobPilot battery is unchanged. `expected_abstention` is optional and defaults to no constraint, so no existing fixture changes behaviour.

## Settled decisions

Twelve decisions have been settled, seven in three rounds on 2026-08-13 and five in three rounds on 2026-08-14, and all twelve are written into the criteria above. Recorded here as a short index, with the reasoning in [rationale.md](rationale.md). **Nothing is open.**

**Round six, raised by experiment 0013.**

**OD-10, decomposition granularity, an over split fragment too atomic to be grounded drops its whole parent: skip a sub claim a sibling already covers, before entailment, and name the residual it opens.** Now **AC-22**, with the relation pinned in Feature design and the work in task 21.

[Experiment 0013](../../experiments/0013-the-connectives-cleared-and-entailment-is-next.md) measured `query-2-resume-generation` abstaining 0 of 6 with **no rejected decomposition at all**. Its decomposition is valid, four sub claims are verified, and `The decision was made.` comes back unsupported while the three that attach its object come back supported. The entailment reason is exact: the evidence does not indicate that a specific decision was made. Experiment 0004 recorded the same shape as `The adapter warns.` before any AC-11 work began, and named it as the opposite of the under splitting the Follow-up tracks. No criterion in this spec reached it, and no tolerance reaches it either, which is the fifth time task 13 was confirmed the wrong instrument and the reason it retires here.

**The prune is permission to skip a check, which is what makes three conditions affordable.** A refused prune costs exactly today's behaviour, so conservatism is free, and the relation is a strict content subset plus matching polarity and modality plus order preservation rather than the single subset test the mechanism needs. Each condition was added against a specific case: without polarity, `The decision was made.` is a subset of `The decision was not made to use X.`; without modality, it is a subset of `The decision may be made to use X.`; without order, it is a subset of a sibling that binds the same words to different objects.

**The residual is rebinding, and it is stated as unclosed rather than narrowed away.** The engineer's first counterexample was rejected by order preservation and the second one is not: against `The team chose client side refetch and rejected background polling.`, the candidate `Client side refetch was rejected.` is a strict subset in order with matching polarity, so it prunes unchecked and asserts the opposite of the evidence. That case is the test, and it asserts the prune **happens**. A test asserting a refused prune would pin nothing, the same reason task 19 built `although it was not` as a case that passes rather than one that fails. What bounds the residual is a property rather than a list. Subsumption is strict and the response is finite, so the ordering cannot cycle, **a maximal claim always exists and always faces entailment**, and the relation prunes only against maximal claims, so every pruned claim's recorded sibling is one that is actually verified. A fabricated content word therefore cannot leave the verification set; it can only be rebound. **The two pass shape came out of the cross check.** The first draft pruned against any subsuming sibling, which lets `subsumed_by` point at a claim that is itself pruned and quietly rests the guarantee on `tokens_match` composing transitively across a chain, which a base set intersection does not do in general.

**Three alternatives were rejected.** A prompt only rule was rejected as the soft half of a split AC-13 already made the other way; it lowers a rate rather than closing a class. Conditioning the drop rule instead, so an unsupported claim drops the parent only when no sibling subsumes it, was rejected because it carries the identical rebinding hole while also paying the entailment call and turning AC-1's absolute rule conditional, and checking a claim and then ignoring its verdict is not more safety than not checking it. Deferring for a rate measurement was rejected because the fixture is stable 3 of 3 and the shape was already on record from experiment 0004.

**OD-11, the JobPilot abstention gates pass on state alone, and a surprising run leaves no evidence: fix the instrument, then pin the cause on query 4 and query 5 together.** Now **AC-23**, with the amendments in **AC-2** and **AC-3** and the work in task 20.

AC-3 recorded its first miss, query 5 answering once at 5 of 6, and the traces that were kept show its abstention resting on wholesale rejection, `not_additive` on `revision` in 3 of 3 dedicated runs. That is the vacuous abstention OD-4 named on the self corpus gate and the Follow-up has carried for the JobPilot gates since experiment 0002. **The miss exposed the weakness rather than caused it**, so the response is to state what the criterion always meant rather than to lower the number to 5 of 6, which would have loosened a fabrication side guard on one observation while leaving the vacuity underneath.

**Query 4 gets the same treatment, and that is the deliberate half.** AC-2 is the only criterion in this chain green on live evidence, and nothing has ever established that its 6 of 6 rests on a verdict rather than on everything being dropped first. Examining query 5 and not query 4 would be choosing which answer to learn. If the pin turns AC-2 red, that is the same finding as AC-3's, recorded as one, and not a regression introduced by the round that looked.

**The instrument goes first because the oracle cannot recover what the harness discarded.** `evaluate` builds each batch in a `TemporaryDirectory` and `EvaluationCheck` keeps four scalar fields, while the port already returns a full traced result, so experiment 0013's single answering run is unattributable forever. Only deviating runs write a trace, so a clean batch costs nothing. Widening `EvaluationCheck` to carry traces was rejected: the report is a summary and a trace is not summary shaped.

**OD-12, every gate in this spec is a fraction of 6 and two batches of identical code passed 2 and 5: four batches of three for anything a decision rests on, forward looking, and a stated rule for what a smaller number may settle.** Now **AC-24**, applied to **AC-2** and **AC-3** in this round.

**The number is four batches rather than more runs per batch, and eighteen runs was rejected on evidence rather than on cost.** One `evaluate` invocation adapts once and ingests once, then runs every fixture `--runs N` times, so the store is constant inside a batch and varies between batches. Experiment 0013's own table separates the two without a single new run: `query-5-uploaded-files` at 2 of 3 and `assertion-rationale-summary` at 1 of 3 vary against a constant store, which is provider variance, while `query-1-private-beta-gate` at 0 of 3 then 3 of 3 splits cleanly on the store boundary. Averaging over both would fold an effect that moved one fixture by three runs of three into the same denominator as one that moved another by one of three, and the larger would vanish into it. **The store split is therefore enrolled as a suspected correctness defect rather than absorbed as noise**, and the reading rule that a figure below the decision grade denominator may not set or move a criterion is part of the criterion rather than advice.

**Round five, raised by experiment 0012.**

**OD-9, which words the AC-11 completeness half must exempt from requiring a parent match: exempt clause relating words by a rule enumerated ahead of the next failure, and give the two halves separate sets.** Now **AC-21**, with the enumeration in Feature design and the work in task 19.

The measured members are `where`, `while`, and `instead`, spanning three grammatical categories and sharing one function. [Experiment 0012](../../experiments/0012-the-other-three-abstentions.md) attributed all three failing fixtures it traced to the same mechanism: each token relates one clause to another, and `DECOMPOSE_SYSTEM_PROMPT` asks for the transformation that dissolves the relation, so no sub claim carries it and the completeness half demands a match for a token the decomposition was right to drop.

**The rule is stated over the function, not the part of speech.** A relative adverb, a subordinating conjunction, and a conjunctive adverb share no category, and experiment 0011's own follow-up asked about subordinating relative adverbs and named `whose` as the next member, a framing `while` fits loosely and `instead` does not fit at all. A rule stated that way would have ratified an edit that still fails the rationale summary assertion. The rule taken instead is decidable by construction rather than by observation: split the sentence into standalone one clause statements and ask whether the word has anything left to do. Its members are enumerated exhaustively today from four closed grammatical categories plus the correlatives, 48 of them after two stated exclusion rules prune the members that fail the rule, so `whose`, `although`, and `however` are closed now rather than after three more live batches. The current set's boundaries were never chosen (`which` exempt but `whose` not, `when` exempt but `while` not, `of` exempt which is why `instead of` looks half exempt already), and this replaces them with a rule that has a reason.

**The whole closed word class was rejected**, though it is the more mechanical test. It exempts for a reason that does not apply: a quantifier is not dissolved by decomposition, since `all records are indexed` splits into sub claims that keep `all`, and the same holds for `every`, `than`, `without`, and `during`. Exempting them would surrender reach the omission guard did not have to surrender, on words that are truth conditional in the way negation is. **Adding only the three measured tokens was rejected** as the growth by failure pattern experiment 0011's follow-up explicitly warned against; it buys one live batch and owes the next decision to the next token.

**The two halves get separate sets, and that is the load bearing half of this decision.** Every measured AC-11 failure is `failure_side=parent`, so nothing measured implicates the additive half, and that half is the guard behind AC-2, the only criterion in this chain green on live evidence at 6 of 6. A shared set would convert each connective from budgeted under `MAX_ADDED_FUNCTION_WORDS` to free, loosening a safety guard on evidence about the other direction, which is the trade OD-8 refused when it rejected `morphology-v1` over 28 invented matches. So the exemption is a skip list read by `response_is_complete` alone, `tokens_match` is not touched, and the matcher argument OD-8 had to make does not have to be made again.

**Two exclusion rules prune the enumeration, and they are part of the membership rule.** A word whose primary use is a content word stays demanded (`provided`, `given`, `granted`, `considering`, `seeing`), and a word whose second use is truth conditional stays demanded (`once`, `still`, `further`, `finally`, `specifically`, `similarly`, `after`, `before`, `since`, `till`, `until`, `than`, `except`, `besides`, `both`, `either`, `neither`). The second rule is the same test that rejected the whole closed class, applied to the enumeration itself, and it removed seventeen of the first draft's sixty five members, in two passes: a cross check caught fourteen, and the engineer's review caught the three correlative quantifiers the cross check and the author had both left in. That is recorded rather than smoothed over: the rules had already been written down and applying them was still not automatic, which is why they sit beside the table in Feature design so a disputed member can be argued against a named rule.

**The cost is stated rather than closed.** This is the second widening of the completeness half in two days and the two compound, so the residual is named in AC-1 and tested in task 19 rather than argued here: a clause carrying no lexical verb, noun, or adjective can now be omitted without failing completeness. **The first statement of that bound was wrong and is corrected in place.** It claimed such a clause carries no proposition, which its own example falsifies: the copulas and negators are already exempt, so `which it was not` is a negated identity built entirely from exempt words, and `although it was not` is the same shape through a new door. The class is enlarged rather than created. What actually holds the line is narrower and specific to the attack: a fabricated decision names an entity, an action, or a property, and every word that does so is a noun, a lexical verb, or an adjective, none of which is ever exempt.

**Round four, raised by experiments 0009 and 0010.**

**OD-8, should the AC-11 verification guard adopt `morphology-v1` (the canonicalizing stemmer spec 0011 pins for lexical retrieval) instead of the pairwise matcher: answer no, and take the base set intersection instead.** Now written into **AC-11**, with the instrument in **AC-20** and the work in task 18.

The reasoning that decides it is that the base set is not a new rule set, it is the symmetric completion of the one already specified. Every pair it newly matches is a pair the five AC-11 rules already accept in one direction; they could not be seen only because the comparison derived `longer` from `shorter` and never reached a common base. No token is ever reduced to a lossy stem, so the over stripping trade [experiment 0010](../../experiments/0010-falls-against-falling.md) left open is **avoided rather than accepted**.

`morphology-v1` was rejected on measurement, not on preference. Measured over 3,690 content tokens it fixes 650 pairs but **loses 30 the shipped matcher already gets right** (`setting` and `settings`, `string` and `strings`, `need` and `needs`, `warning` and `warnings`) and **invents 28 false matches** (`file` and `fill`, `site` and `sits`, `role` and `rolling`, `bar` and `bare`). The false matches are what decide it. Twenty eight false matches means the additive half accepts twenty eight substitutions it currently rejects, and that guard is what makes **AC-2** pass 6 of 6, the only criterion in this chain currently green on live evidence. Trading the fabrication win for the answering win is the worst outcome available here. The base set adds zero false matches, so the guard's strength is provably unchanged.

A hand enumerated inflection bridge was also rejected: enumerating the specific participle to finite pairs is the same defect one layer up, and the next inflection gap would need another patch.

**This is a correction, not a second decision, which is why it amends AC-11 in place rather than taking a new spec number.** AC-11 already said two tokens match when they share a stem, and `_stem_match` already documented itself the same way. Sharing a stem is symmetric; the enumerated rules implemented something directional. The base set makes the implementation do what the criterion always claimed. A new number would put a decision shape in this repository's own corpus for a decision nobody made, which is the standing rule this project set after [experiment 0001](../../experiments/0001-self-query-on-own-specs.md).

**Round three, raised by experiment 0006.**

**OD-7, coverage rejects a sentence that states what the system does when the facet asks what was decided: answer no, and fix it in generation rather than in coverage.** Now **AC-18**, with the measurement contract in **AC-19** and the work in task 17. Experiment 0006 isolated the cause by controlling for both the AC-16 exclusion and sentence survival.

The evidence. Against the frozen fixture, the gate's decision query emitted this sentence and coverage left the facet uncovered:

```text
S1: The hybrid retrieval system uses a combination of lexical BM25 and semantic
    Chroma retrieval, followed by reciprocal rank fusion to combine their
    contributions.

uncovered F1: What was decided about hybrid lexical and semantic retrieval?
```

Across 6 runs, 11 sentences reached coverage and none covered the single facet. AC-16's exclusion is not the cause: removing it produced one coverage in 6 runs, and that one covered with the caveat sentence, which is the OD-5 defect AC-16 was written to close. The exclusion is working, and this is a separate fourth cause alongside `not_additive`, inline markers, and over splitting.

The mismatch is one of framing. The facet asks what was **decided**; the sentence says what the system **uses**. AC-12's directness rule reads a statement of fact about the system as not a statement of a decision, which is a defensible reading of the rule as written. The corpus stores decisions, generation writes descriptions of systems, and coverage asks for a decision framing it never receives.

**It blocked the AC-15 answering bar, and task 13 could not move it.** Calibration raises how many sentences survive verification; survival was not the binding constraint, since 11 sentences already reached coverage and none covered.

**The answer is no**, and the rule is pinned in AC-12 rather than relaxed: a sentence stating what the system does does not state a decision. Coverage was reading the rule correctly and the rule never said so, since its exclusion list stopped at a reason, context, consequence, premise, or anaphoric fragment. What changes is generation, which was being asked what was decided from prose that never said it was a decision. The pipeline already carried the answer and dropped it: every accepted chunk knows its `value_path`, and `query.py` forwarded only the text, while the embedding side has rendered that same field above that same text since spec 0007. Generation now receives a `Field:` line in plain words and an instruction to answer a decision facet with the decision.

The rejected options. **`COVERAGE_SYSTEM_PROMPT`** was rejected because experiment 0006 measured what relaxing that stage does: removing the AC-16 exclusion produced one coverage in 6 runs and it covered with the caveat sentence, the exact OD-5 defect. A caveat and a description are both statements about the system, so no wording there separates them reliably, and under AC-4 a real decision statement routinely carries a descriptive clause, so tightening instead would reject the sentences this fix exists to accept. **Facet extraction** was rejected because it changes the question the user asked; the gate's decision query means what it says. **Giving coverage the citations** was rejected as the sharpest of the three and the worst for the gate: the AC-15 co location check is the oracle's only defence against a caveat, and telling coverage that citing `decision.chosen` is what makes a sentence state the decision hands coverage the oracle's own criterion, so every covered run would satisfy the oracle by construction and the gate would stop discriminating. It would also merge grounding into directness, which the code separates today, since coverage receives sentence text and nothing else.

Two sub decisions came with it. The label is **plain words, never the dotted `value_path`**, because a dotted path survives tokenization as one unmatchable content token and an echo would fail the completeness half unconditionally, reproducing the AC-13 failure in a class a strip cannot close: `ch_` plus 64 hex cannot occur in prose, a dotted path is lexically ordinary, and the value path grammar is open. Plain words remove the failure rather than catch it, and they are also closer to the outcome being measured. And **`record_title` is not passed**, because it is adapter extracted corpus content inside a block already fenced as untrusted; `value_path` is a closed vocabulary this project's own chunker writes.

**Round two, raised by experiment 0004.** OD-4 and OD-5 came out of one trace, and the third item is the deviation that experiment recorded for ratification.

**OD-5, coverage accepted a caveat as covering a decision facet: state the exclusion to the model, count the miss, and hold the deterministic guard behind a number.** Now **AC-16**, with the work in task 16. The trigger is a number rather than a condition: 2 or more misses in the 6 gate runs after the instruction change. The AC-15 oracle is the counter, so the measurement costs nothing extra.

**OD-6, the coverage schema `description` deviation: ratified, instance and pattern, under two bounds with a named owner.** Now **AC-17**, with the work in task 16. A description may only restate a rule a named validator already enforces, and may never be the only place a rule is stated. `/check review` is where the bound is looked for, and the review names the enforcing function; without an owner the bound is prose that drifts, which is the same failure as AC-11 being described rather than pinned.

# 0010. Abstention verification reliability

**Date**: 2026-08-12
**Status**: In Progress

## Summary

The query pipeline verifies atomic sub claims, and it emits whole sentences. Decomposition is a check on a draft sentence, not a rewrite of it. A sentence reaches the answer only when its decomposition is valid (it adds nothing to the parent and omits nothing from it) and every sub claim is supported by the evidence. Otherwise the whole sentence is dropped and contributes nothing. Coverage then judges whole sentences, so a decision that takes several clauses to state can still be answered, while a fabricated clause still takes its whole sentence down with it.

## Requirements

**User stories**:
- As a user of the query command, I want an honest abstention when the evidence does not support a claimed decision, so that I am not shown a cited answer that mixes a fabricated decision with a real borrowed clause.
- As an operator, I want the debug trace to show how each sentence was split and why each piece survived or was dropped, so that a bad split is visible rather than silent.

**Acceptance criteria** (the contract, each IDed and independently checkable):
- **AC-1**: A draft sentence that welds a fabricated decision to a verbatim borrowed clause is decomposed and verified by sub claim. The fabricated sub claim comes back unsupported, and its whole parent sentence is dropped, so the fabrication cannot reach output and neither can the borrowed clause that was carrying it. A decomposition that omits the fabricated clause entirely fails the completeness half of AC-11, so the parent is dropped there too rather than emitted as safe. Deterministic tests cover both attacks: an explicit fabricated sub claim, and an omitted one.
- **AC-2**: Live gate against the real JobPilot corpus: query 4 abstains in every run of two separate `--runs 3` batches, 6 of 6 total. The trace must show that the fabricated decision sub claim came back unsupported, that its parent sentence was dropped for that reason, and that the facet asking what was decided is uncovered. The check reads two paired rows: a row in `decomposed` whose `entailment` is `unsupported`, and the matching `dropped_sentences` row for its parent with reason `unsupported_sub_claim`. A checker reading a lexical disposition instead would call a passing run failed, since a fabricated clause is an entailment failure, not a vocabulary one. The abstention proves the complete answer contract, while AC-1 proves the weld fix itself.
- **AC-3**: Live gate against the real JobPilot corpus: query 5 abstains in every run of the same two batches, 6 of 6 total. This is a smoke gate, not a measured abstention rate.
- **AC-4**: The answer is made of whole draft sentences. A sub claim is never emitted, and it exists only in the trace. A sentence is emitted verbatim, with its available citations and its own sentence id, when both hold: its decomposition is valid under AC-11, and every sub claim in it is supported. If either fails, the whole parent sentence is dropped and contributes nothing; other sentences are unaffected. Draft order is preserved among the emitted sentences. Coverage then decides answered versus abstained over those sentences. A facet is covered only when one emitted sentence directly states its answer. Coverage cannot combine sentences, and a reason, context, consequence, premise, or anaphoric fragment cannot cover a decision facet unless that same sentence states the decision. One sentence may cover several facets only when it directly answers each one.
- **AC-5**: A sentence whose whole text is contained in an available cited chunk is never decomposed and never pays the decomposition call. A deterministic unit test proves the cost bound. This criterion depends on **AC-13**: a sentence carrying an inline chunk id marker can never be a substring of the chunk text it cites, so before AC-13 the shortcut was unreachable for every marker bearing sentence and the cost bound was silently dead. Experiment 0003 measured markers on 11 of 20 sentences, so the bound was dead for roughly half of them.
- **AC-6**: The debug trace shows every decomposition row and every sub claim verdict, and it answers one question for each draft sentence: did this sentence reach the answer, and if not, why. A genuine empty response appears only in `empty_decompositions`. An invalid nonempty response appears in `rejected_decompositions` with the sentence id, returned count, and one closed disposition: `over_cap`, `duplicate`, `not_additive`, or `incomplete`. Every sentence that does not reach the answer records exactly one row in `dropped_sentences` with its sentence id and one closed reason: `no_available_citations`, `decomposition_invalid`, or `unsupported_sub_claim`. A `decomposition_invalid` row always pairs with a `rejected_decompositions` row carrying the specific disposition, so the two are one event described at two levels, never two events. Rejected or unsupported claim text is not exposed. A sub claim row keeps its own `entailment` verdict so an `unsupported_sub_claim` drop can be traced to the exact claim that caused it.
- **AC-7**: A provider failure during the decomposition call returns a failed query result with a provider failure trace, consistent with the existing entailment and coverage failures. A test proves the failure contract.
- **AC-8**: Before any containment or provider call, parent citation ids are deduplicated in parent order and split into `available_citations` (ids in accepted context) and `missing_citations` (the ordered remainder). Every containment, decomposition, entailment, and output citation uses only `available_citations`. With none available, the sentence is removed without a provider call. Missing ids are trace only and can never appear in answer citations. A `missing_chunk_refs` row is recorded for every sentence with a nonempty missing set, whether or not that sentence proceeds on its available citations.
- **AC-9**: The change does not newly fail the other live fixtures through a verification regression, checked as a smoke gate, not a rate comparison: three runs cannot separate a real regression from the fixture level variance the fresh baseline itself showed (query 1 went 1 of 3 on a provider hiccup with no code change involved). The bars are named so the gate needs no judgment call at read time. In the same two `--runs 3` batches used for AC-2 and AC-3, the incremental reingest assertion passes in both batches (it is a per batch assertion, not a per run one), the unverifiable claim assertion passes in at least 5 of the 6 runs, and the rationale summary assertion is **re measured rather than asserted**. Its earlier 5 of 6 bar was earned by the per sub claim drop, which AC-11 no longer has, so carrying that bar forward would be a claim this spec cannot support. The recorded evidence is against it: one of its rejected sub claims substituted the synonym `goal`, and no stem rule can ever match a synonym, so the AC-11 retry is the only thing that might recover it. Task 14 records the measured figure and the trace disposition behind it. A shortfall is a finding to act on, not a gate failure, until a bar is set from that measurement. The 5 of 6 bar is set by the live provider variance already documented for query 1, not by preference; a shortfall below it fails AC-9 rather than being argued about. Query 3 may abstain under strict coverage when the generated answer does not directly state every facet; that is the directness rule working as intended, and the generation quality gap is a follow up, not a coverage regression. Query 1's occasional provider failed state is a live hiccup, not a signal to compare against.
- **AC-10**: `schema_version` stays 2. The additive verification trace fields are `decomposed`, `empty_decompositions`, `rejected_decompositions`, `dropped_sentences`, and `missing_chunk_refs`. They default to empty tuples so an older constructor call remains valid. Named fields resolve, and JSON gains fields without removing or renaming any existing field. `dropped_sentences` replaces the `dropped_sub_claims` field of the earlier draft, which described an event that can no longer occur; the field count is unchanged and nothing else is renamed. The runtime does not read persisted query results, so no data migration is needed.
- **AC-11**: The lexical check is a deterministic decomposition validity test on the response as a whole. It decides whether the sub claims are a faithful division of the parent sentence, so that verifying them is the same as verifying the parent. It is not a proof that actors, negation, scope, order, or factual relations were preserved; entailment remains responsible for factual support. Tokens use Unicode NFKC, case folding, line ending normalization, whitespace splitting, and edge punctuation stripping; internal apostrophes and hyphens remain. Two tokens match when they share a stem under these exact rules, where `shorter` and `longer` name the two tokens by length: `longer` equals `shorter`; or `longer` equals `shorter` plus `s`, `es`, `ed`, or `ing`; or `longer` equals `shorter` with its final `e` removed plus `ed` or `ing` (`use` and `using`); or `longer` equals `shorter` plus a repeat of `shorter`'s own final character plus `ed` or `ing` (`ship` and `shipped`); or `longer` equals `shorter` with its final `y` replaced by `i` plus `es` or `ed` (`rely` and `relies`). The **four inflection rules** additionally require `shorter` to be at least three characters, measured on the untransformed token. **Exact equality carries no floor**: it transforms no suffix, so the floor guards nothing there, and a token already present in the parent is not new vocabulary however short it is (`db` reused verbatim must match). A function word matches only by exact normalized token equality, never by stem. When a sub claim token could match more than one eligible parent token, take the **first unused parent token in parent order**; the assignment is greedy and never backtracks, so two conforming builds reach the same verdict. The test has two halves, and a response must pass both. **They have deliberately different scopes**:
  - **Not additive**, scoped **per sub claim**: each sub claim is checked alone against the full parent token pool, and the pool resets for the next sub claim. Every content token in that sub claim must match an unused parent content token within that one comparison. This stops a sub claim substituting content the parent never had. The scope is per sub claim because a decomposition restates the shared subject in each part, which is normal and adds nothing: consuming those tokens response wide would reject a correct split of any sentence with a repeated subject. A function word token from the closed set in Feature design may be added without a parent match, at most two instances per sub claim, counted as instances whatever the words are.
  - **Complete**, scoped **across the whole response**: every distinct content token of the parent must match a token in at least one sub claim. Matching here is presence based, not multiset based: one occurrence in one sub claim satisfies every occurrence of that token in the parent. This stops the decomposition quietly dropping a clause, which is the omission attack of AC-1, because a dropped clause takes its content words out of the response entirely. Parent function words need no match.

  A response that fails either half is invalid. Its parent sentence is dropped, no entailment call is made for it, and the trace records the disposition. **There is no per sub claim drop.** Removing a sub claim from a response would break the completeness half by construction, so the granularity question the earlier drafts asked (whole response or per sub claim) does not arise: validity is a property of the response, even though one of its halves is measured per sub claim. Reordering is allowed. The checks run in this fixed order, each without calling entailment: a malformed row (empty text after trimming) fails first as `provider.decompose`; then a genuine empty array; then more than 8 rows as `over_cap`; then a normalized duplicate row as `duplicate`. The two half test runs only on a response that survives all four, and fails as `not_additive` or `incomplete`. A response that fails the two half test gets **one decomposition retry** at the same fixed settings; if the retry is also invalid, the parent is dropped. The retry exists because an invalid decomposition is usually a stochastic paraphrase rather than a property of the sentence, and it mirrors the single schema repair attempt the other provider calls already make.
- **AC-12**: The ordered canonical facet tuple is the single output of `extract_facets(original_question)` and is stored in `GenerationTrace.facets`, then passed unchanged to answer generation and coverage. The directness rule below is unchanged from the earlier draft, but it now judges whole emitted sentences rather than sub claim fragments. That is what makes it workable: a decision stated across several clauses is one sentence, so requiring one sentence to state a facet's answer no longer rules out multi part decisions, and the no combining rule stops being a trap. Coverage uses the same fixed model constant as facet extraction and answer generation, at temperature 0. With no emitted sentences, the application creates one uncovered row per facet with reason `no emitted answer sentence` and makes no coverage call. That reason string is renamed from `no kept answer sentence`, because `kept` described a sub claim surviving on its own, which can no longer happen. Otherwise the provider returns exactly one row for every facet, in canonical facet order. Validation rejects unknown, missing, duplicate, or out of order facet ids; unknown, duplicate, or out of emitted order sentence ids; a covered row with no sentence id; or an uncovered row with sentence ids. A schema failure gets the existing single repair attempt, then fails as `provider.coverage` at `claim_verification`. The live query 4 gate requires separate decision and reason facets. Its report classifies a failure from the existing trace: a missing separate decision facet is `facet_extraction`; separate facets with the decision facet wrongly covered is `coverage_directness`; separate facets with the decision facet uncovered but an answered result is `query_state`. No new trace field is added.
- **AC-13**: `DraftSentence.text` never contains a chunk id. `validate_draft` removes every chunk id marker from the raw text **before every other check on that text**, so the one sentence check, the empty text check, and the duplicate text check all read the cleaned string. A sentence whose text is nothing but a marker therefore fails as empty text rather than reaching output. The matcher is pinned as a literal regular expression rather than described, because a described shape is what two earlier cross checks caught AC-11 leaving ambiguous. A bare marker is `(?i)\bch_[0-9a-f]{64}\b`; a bracket group is `(?i)\[\s*ch_[0-9a-f]{64}(?:\s*,\s*ch_[0-9a-f]{64})*\s*\]`. Bracket groups are removed first, then any remaining bare marker, then the whitespace is repaired in three fixed steps: runs of whitespace collapse to one space, a space immediately before one of `.,;:!?)]}` is removed, a space immediately after one of `([{` is removed, and the result is trimmed. The punctuation steps are not cosmetic. Without them the common case leaves `chosen [ch_...].` as `chosen .`, which the token matcher tolerates (a bare punctuation token is dropped) but which reaches the reader as visibly broken prose in the emitted answer, and AC-4 emits the sentence verbatim. Three rules the shape alone does not settle: matching is **case insensitive**, so a model that uppercases a hash cannot smuggle one through even though `chunk_id` only ever emits lowercase; the comma separator tolerates any or no surrounding whitespace, since experiment 0003 recorded the model writing `", "` while the debug renderer writes `","`; and a bracket group holding anything besides markers and separators is **not** a marker group, so `[see ch_abc...]` loses only its bare marker and keeps its brackets and prose. `chunk_ids` is not touched and stays the only citation source. Because the duplicate text check reads the stripped string, two draft sentences whose prose is identical and whose markers differ now collide and fail the response as a duplicate; that is the intended reading, since the marker was never content and identical prose is genuinely duplicate. `ANSWER_SYSTEM_PROMPT` keeps naming the real bracketed ids from the evidence, because dropping that wording makes a live model invent its own ids and fail every validation attempt, and it additionally forbids writing an id inside the sentence text. Deterministic tests prove that a marker never survives into `DraftSentence.text`, in the bracketed multi id form and the bare form, that a marker only sentence fails as empty, that a mixed bracket group keeps its prose, and that the duplicate collision above is reached; the prompt half is measured by the live gate, not by a unit test, since it changes how often the strip fires rather than whether it works.
- **AC-14**: The self corpus gate reads a **frozen corpus fixture**, never the live `docs/specs/` tree. A committed script, `docs/experiments/data/build-self-corpus-fixture.sh`, generates the fixture into `docs/experiments/data/self-corpus-fixture/`, whose own corpus root is that directory and whose records therefore live at `docs/experiments/data/self-corpus-fixture/docs/specs/`. That placement is outside `docs/specs/`, so `adapt` at the repository root cannot discover it: discovery reads `corpus_root/docs/specs` and iterates its direct children only, so a tree nested deeper is structurally invisible rather than merely filtered. The fixture excludes the `0010-abstention-verification-reliability` directory. Beside it the script writes `manifest.json`, whose shape is pinned in Feature design, carrying the source commit, the excluded spec, a **sha256 over the raw bytes of each copied file**, and the gate's queries with their expected record and expected result state. Raw bytes rather than the adapter's own `fingerprint()`, because this hash exists to detect drift of the fixture input; `fingerprint()` also moves on an `ADAPTER_VERSION` bump, which would report adapter churn as corpus drift. Regenerating the fixture against a changed working tree therefore produces a visible diff rather than a silent change to the measurement input. The gate's queries and their expected records live in that manifest, outside the corpus entirely, and never in a spec. **Stated assumption, verified once, not assumed forever**: the fixture is a faithful stand in for the frozen live corpus only for the chunk text the gate reads, not for the whole adapted record. `_extract_code_paths` resolves inline code spans against the corpus root, and the fixture root holds no `src/` or `tests/` tree, so the `src/decision_memory/...` paths every spec cites do not resolve there and each record's `evidence` set is smaller and its `mentions_unresolved` count higher than a live adaptation would produce. Task 11 checks once that a record's active chunk set is identical between a live and a fixture adaptation; identical chunks confine the divergence to the `evidence` field, which the gate's answers do not read. A difference invalidates the fixture and is a finding, not a pass.

## Decision

**Chosen option**: Option 1 revised: sub claim decomposition as a verification check on the parent sentence, with whole sentence output, plus strict complete facet coverage.

The **verification unit** is the sub claim. The **output unit** is the sentence. The earlier draft made these the same thing, and experiment 0002 showed that this is the flaw: splitting the answer makes coverage unreliable in both directions at once, accepting fragments that say too little and refusing fragments that each say part of the truth.

The application first resolves the parent citation ids against accepted context. A sentence fully contained in one available cited chunk keeps the whole sentence path and only its available citations. Every other sentence with available evidence is decomposed by `gpt-4o-mini`. The response is then tested for validity as a whole under AC-11: it must add no content to the parent and omit none of it. An invalid response drops its parent sentence and makes no entailment call. In a valid response every sub claim is verified alone, containment first, then entailment. If every sub claim is supported, the parent sentence is emitted verbatim with its available citations. If any sub claim is unsupported, the parent sentence is dropped whole. Sub claims never reach output; they exist to decide the fate of the sentence they came from.

Coverage remains binary and independent over the canonical facet tuple. A query is answered only when every facet is directly answered by one emitted sentence. Coverage never composes an answer across sentences. Reasons alone cannot cover a decision facet. This is a targeted enforcement of spec 0007 AC-15. It does not solve query 2 citation completeness, because that missing record is not represented by a fixed facet and remains a follow up.

## Feature design

**Data model sketch**:

New entity, the sub claim, held only in the verification trace, no persistence:

- `sub_claim_id`: str, `f"{sentence_id}.{i+1}"`, 1 based over the decomposition response order. A duplicate under `normalize_for_containment` invalidates the whole response. Ids are contiguous, because a sub claim is never removed from a valid response
- `sentence_id`: str, the parent DraftSentence
- `text`: str, the atomic claim
- `contained`: bool, whole sub claim verbatim in a cited chunk
- `entailment`: str, one of `skipped` (contained, no model call), `supported`, `unsupported`
- `reason`: str, the entailment reason, empty when skipped
- `citations`: tuple of available chunk ids that support this sub claim. Trace only, since a sub claim is never emitted. A contained sub claim narrows to the matching available chunks; an entailment grounded one keeps all available citations because `entail_verdict` has no per chunk attribution

There is no `kept` field. A sub claim does not survive or fail on its own; it contributes its verdict to the parent sentence, and the parent is what survives or fails.

New entity, the dropped sentence, held only in the verification trace:

- `sentence_id`: str, the draft sentence that did not reach the answer
- `reason`: str, one of `no_available_citations`, `decomposition_invalid`, `unsupported_sub_claim`
- no claim text is recorded

New entity, the rejected decomposition, held only in the verification trace:

- `sentence_id`: str, the parent sentence
- `returned_count`: int, the number of rows returned before rejection
- `disposition`: str, one of `over_cap`, `duplicate`, `not_additive`, `incomplete`

`VerificationTrace` gains five additive fields:

- `decomposed`: tuple of sub claim rows, for every sub claim of a valid response, default `()`
- `empty_decompositions`: tuple of sentence ids whose provider response contained zero sub claims, default `()`
- `rejected_decompositions`: tuple of invalid whole responses, with no rejected claim text, default `()`
- `dropped_sentences`: tuple of dropped sentence rows, with no claim text, default `()`
- `missing_chunk_refs`: tuple of (sentence_id, missing chunk ids), the upstream signal when generation cited chunks that retrieval did not surface, default `()`

**State transitions** (verification pipeline):

Per draft sentence, resolve available and missing citations. With no available citation, drop the sentence, record the missing ids, and record a `no_available_citations` row. Otherwise run whole sentence containment against available chunk text only; if it passes, emit the parent with its available citations and make no further call. If it fails, decompose using the same available evidence, then test the response for validity: genuine empty, then over cap, then duplicate, then the two half lexical test of AC-11 (not additive, then complete). An invalid response records its `rejected_decompositions` disposition and a `decomposition_invalid` row, drops the parent, and makes no entailment call. A valid response has every sub claim verified against available evidence, containment first then entailment. If every sub claim is supported, emit the parent sentence verbatim with its available citations. If any sub claim is unsupported, drop the parent and record an `unsupported_sub_claim` row. Preserve draft order across the emitted sentences. If no sentence remains, create deterministic uncovered rows without a coverage call; otherwise run coverage against the unchanged canonical facet tuple and the emitted sentence tuple. Any uncovered facet abstains. An abstained result exposes no public sentences or citations, while its trace retains the verification rows.

**API surface**:

No new command, no new flag, no new endpoint. The debug trace and JSON output gain the five additive verification fields above. Top level `QueryResult` is unchanged, `schema_version` stays 2.

| Surface | Change |
|---|---|
| `query --debug` | gains a Sub claims section listing sub claim rows, genuine empty responses, invalid response dispositions, dropped sentence rows, and missing chunk refs |
| JSON `QueryResult.trace.verification` | gains `decomposed`, `empty_decompositions`, `rejected_decompositions`, `dropped_sentences`, `missing_chunk_refs` |

**Provider contracts**:

Available evidence is assembled once per parent. Scan `DraftSentence.chunk_ids` in order, keep the first occurrence of each id, and look it up only in accepted context. Provider evidence uses available citation order. Each block is `CHUNK {chunk_id}:\n{text}`, joined with `\n\n---\n\n`. Containment, decomposition, and entailment all use this same lookup and order.

Decomposition receives the exact parent sentence plus the available evidence blocks. It uses `gpt-4o-mini`, temperature 0, and the existing single schema repair attempt. Its structured response is `{"sub_claims": [{"text": "nonempty string"}]}`. The provider prompt says at most 8, but the response schema leaves the array unbounded so the application can classify an over cap response instead of mislabeling it as provider failure. Text is trimmed and provider order is preserved. Empty text after trimming is malformed. Text repeated under `normalize_for_containment` rejects the complete response as `duplicate`. A malformed row fails as `provider.decompose`. A valid empty array removes the sentence and records a genuine empty. An over cap or duplicate response removes the sentence and records its closed rejection disposition.

**Prompt constants.** Prompt text is a spec constant, not a build time choice, so the exact shipped strings are recorded here. Two of them changed after the first draft and are written out in full.

`DECOMPOSE_SYSTEM_PROMPT` asks for both directions the validity test measures. The additive direction alone is not enough: a response that omits a clause is rejected as `incomplete` and takes its whole parent down, so a prompt that never asks for completeness makes the AC-11 hard gate fire on correct behaviour. The shipped text is:

```text
Split the candidate sentence into atomic factual sub claims. Each sub claim
must be one atomic assertion stated nearly verbatim, using only words and
facts already present in the candidate sentence. Return at most 8 sub claims.
Never introduce content that is not in the candidate sentence. Cover the whole
sentence: every clause of it must appear in some sub claim, and leaving a
clause out is an error. If the sentence is already a single atomic claim,
return it as one sub claim.
```

`ANSWER_SYSTEM_PROMPT` is reworded for AC-13. It keeps naming the real bracketed ids, which is load bearing (without that wording a live model invents its own ids and every validation attempt fails), and it moves them explicitly into the `chunk_ids` field while forbidding them in the sentence text:

```text
Write short factual answer sentences that directly answer the given facets,
using ONLY the provided evidence chunks. Every sentence must be a single
complete sentence and list 1 to 8 chunk ids it is directly supported by in
the chunk_ids field, copied exactly as shown in brackets in the evidence.
Never write a chunk id inside the sentence text itself. Number the sentences
S1, S2, and so on. Never invent facts outside the evidence. If the evidence
cannot answer a facet, write nothing for it.
```

The prompt is the soft half of AC-13 and the strip is the hard half. The strip is what makes the guarantee, since the model complied inconsistently before (11 of 20 sentences carried a marker); the prompt only lowers how often the strip has to fire.

The lexical test runs on the decomposition response as a whole against the parent sentence, in both directions, under the exact normalization, stem, bound, and ordering rules of AC-11, which is the single normative statement of the matcher. This section adds only the token set it refers to.

The function word set is closed and exhaustive, a spec constant rather than a grammatical category the builder extends. It is exactly `a`, `an`, `the`, `and`, `that`, `which`, `is`, `are`, `was`, `were`, `be`, `been`, `being`, `has`, `have`, `had`, `do`, `does`, `did`, `can`, `could`, `will`, `would`, `shall`, `should`, `may`, `might`, `must`, `to`, `of`, `for`, `with`, `by`, `as`, `at`, `on`, `in`, `from`, `about`, `so`, `but`, `or`, `if`, `because`, `when`, `then`, `there`, `it`, `this`, `these`, `those`, `their`, `not`, `no`, `never`, and `nor`. Any token outside this set is a content token. In the additive direction, checked per sub claim against a fresh parent pool, a content token must find an unused parent match. In the completeness direction, checked across the whole response by presence, a distinct parent content token must appear in at least one sub claim. Function words are exempt in the completeness direction and bounded in the additive one. Closing the set errs toward dropping a sentence, which is the safe direction, and an unlisted word that shows up in practice is a spec edit, not a build time judgment.

A response containing a genuinely new content word fails as `not_additive`. A response that leaves a parent content token unmatched fails as `incomplete`. Either failure drops the parent sentence and records one `rejected_decompositions` row plus one `decomposition_invalid` row in `dropped_sentences`. Rejected claim text is never recorded.

Coverage receives the original question, the canonical facets in facet order, and the emitted sentences in output order. Its fixed system instruction is: `For each facet, decide whether one provided answer sentence directly states its answer. Judge only what that sentence says. Do not combine sentences. A reason, context, consequence, premise, or anaphoric fragment does not state a decision. One sentence may support several facets only when it directly answers each one.` It uses `MODEL_FACETS_AND_ANSWER`, temperature 0, and the existing single schema repair attempt. Its response schema remains one row per facet with `facet_id`, `covered`, nonempty `reason`, and `sentence_ids`. Supporting ids are unique and follow emitted sentence order.

**Gate fixture manifest** (AC-14). The shape is pinned here because task 10 writes it and task 11 reads it back, and two builds inventing their own shapes is the exact gap this spec exists to close. `docs/experiments/data/self-corpus-fixture/manifest.json`:

| decompose sentence | ordered sub claim texts | validated `gpt-4o-mini` structured response, with the fixed model settings and schema above |
| decomposition validity | valid, or one closed invalid disposition | the AC-11 two half matcher: the additive half per sub claim against a fresh parent pool, the completeness half across the response by presence, both under the exact stem rules, the greedy first unused parent order tie break, the function word bound, and the closed function word set in Provider contracts; malformed row, empty, over cap, and duplicate run first in that order; one retry on a two half failure |
| decomposition trace | sub claim rows, genuine empty id, or invalid disposition row | validated provider response and verification rows; exact empty array; or closed application disposition |
| per sub claim containment | contained bool, matching chunk ids | deterministic containment against each available cited chunk individually |
| per sub claim entailment | supported bool, reason | existing entailment call against the ordered available evidence blocks, only when containment failed |
| sentence survival | emitted bool | decomposition valid AND every sub claim `contained or entailment == "supported"`; there is no per sub claim survival |
| dropped sentence reason | one closed reason per unemitted sentence | `no_available_citations` from the citation partition; `decomposition_invalid` from the validity test; `unsupported_sub_claim` from the entailment verdicts |
| emitted sentence citations | ordered available chunk ids | the parent's available citations, deduplicated in parent order; sub claim level citations stay in the trace only |
| answer sentence id and order | sentence id and stable output position | the parent `DraftSentence` id; draft order among emitted sentences |
| public answer content | whole sentences and citations, or none | emitted parent sentences only, and only for an answered result; an abstained result exposes them only through trace |
| missing chunk ref signal | sentence id and ordered missing ids | the missing side of the citation partition, never an output citation source |
| facet coverage | one ordered row per canonical facet | deterministic uncovered rows when there are no emitted sentences; otherwise the validated coverage response from the fixed contract above |

**Key invariants**:
- A chunk id never appears in `DraftSentence.text`. Citations travel in `chunk_ids` only, and the strip runs at the generation boundary, so no rule downstream has to know that a chunk id is not a word. Every later consumer of `text` (the containment shortcut, the token matcher, the rendered answer) inherits the guarantee instead of re deriving it.
- A gate never reads the document that defines it. The self corpus fixture excludes this spec, and the gate's expected answers live in the fixture manifest outside `docs/specs/`, so no spec can become a source for the answer its own gate checks.
- The accepted context lookup is the only source of provider evidence and output chunk citations. Missing ids remain trace only.
- A sub claim is never emitted. Only whole parent sentences enter coverage or public output; sub claims decide which parents survive.
- A parent sentence is emitted only when its decomposition is valid and every sub claim is supported. Either failure drops the parent whole. There is no partial sentence.
- The additive half is measured per sub claim against a fresh parent pool; the completeness half is measured across the whole response by presence. Applying either scope to the other half is a defect: response wide consumption rejects a correct split that restates its subject, and per sub claim completeness rejects every split of more than one clause.
- The lexical test proves only that the sub claims neither add content to the parent nor omit content from it, under its token rules. It does not prove factual equivalence or relation preservation. A decomposition that preserves every content token while inverting the meaning passes it; entailment is the only check that can catch that.
- A sub claim is never removed from a response. Removing one would break the completeness half by construction, so validity is a property of the whole response, never of an individual sub claim.
- Decomposition runs only after whole sentence containment fails against available evidence. No available evidence removes the sentence without a provider call.
- Grounded is `contained or entailment == "supported"`, the existing binary verdict. There is no separate acceptance threshold.
- Grounding decides whether a sentence is supported. Coverage separately decides whether that one sentence directly answers a required facet.
- Coverage uses the canonical facet tuple unchanged. Exactly one valid row per facet is required in the same order. A covered row names one or more unique known emitted sentence ids. An uncovered row names none.
- Coverage cannot combine sentences. One sentence may appear in several rows only when it directly answers every named facet.
- Query 4 diagnosis reads `GenerationTrace.facets`, coverage rows, uncovered facets, and result state in that order. A merged decision and reason facet is assigned to facet extraction before coverage is judged. Separate facets make coverage directness independently diagnosable.
- Provider schema failure receives one repair attempt. Final decomposition or coverage failure fails the query at `claim_verification`; it never becomes abstention.
- `schema_version` stays 2. The runtime reads no persisted query result, and all five trace additions are output only.

**Security model**:

No new surface. Decomposition sends the candidate sentence and available cited chunk text to the existing provider, the same class of data entailment already sends. Rejected claim text is not added to the trace or normal output.

**Configuration required**:

None. Decomposition and entailment stay fixed to `gpt-4o-mini`. Coverage uses `MODEL_FACETS_AND_ANSWER`. All calls use temperature 0. There is no acceptance threshold to configure. The cap, lexical matcher, prompt text, schemas, and dispositions are spec constants, not settings.

**Critical test scenarios**:
- Fabrication removal: a fused sentence returns both grounded and fabricated sub claims; the fabricated one is unsupported, so the whole parent is dropped and the grounded clause does not survive on its own, verifies **AC-1**, **AC-4**
- Omission attack: decomposition returns only the grounded clause and omits the fabricated one; the response fails the completeness half, so the parent is dropped as `incomplete` with no entailment call, verifies **AC-1**, **AC-11**
- Whole sentence output: a sentence whose decomposition is valid and fully supported is emitted verbatim, with its own sentence id and its parent citations, in draft order among the other emitted sentences; no sub claim text appears in output, verifies **AC-4**
- Accepted context boundary: missing citations are removed before whole containment; a sentence that proceeds on its available ids still records its `missing_chunk_refs` row; no output citation names a missing id, verifies **AC-8**
- Citation precision: an emitted sentence cites its parent's available ids deduplicated in parent order, while sub claim level containment and entailment citations stay in the trace, verifies **AC-4**, **AC-8**
- Decomposition outcomes: valid, actual empty, over cap, normalized duplicate, `not_additive`, and `incomplete` remain distinct in trace; the whole response checks fire in their stated order before the two half test; every invalid response writes exactly one `rejected_decompositions` row and one paired `decomposition_invalid` row, verifies **AC-6**, **AC-10**, **AC-11**
- One drop reason per sentence: a sentence with no available citations, an invalid decomposition, and an unsupported sub claim each produce exactly one `dropped_sentences` row with the right closed reason, and no sentence produces two, verifies **AC-6**
- Lexical limits, additive direction: `refetch` and `refetches` match, `use` and `using` match under the dropped `e` rule, `add` and `adding` match under the plain suffix rule, `ship` and `shipped` match under the repeated final character rule, `rely` and `relies` match under the `y` to `i` rule, a two character token matches itself exactly but never inflects, two added function word tokens pass while a third fails, an unlisted function like word is treated as content and fails, and a new content token fails the response as `not_additive`, verifies **AC-11**
- Additive scope: the experiment 0002 decomposition, three sub claims each restating `The hybrid retrieval system` against a parent naming it once, passes because the pool resets per sub claim. The same input fails if a build consumes response wide, so this test pins the scope and guards the exact regression the cross check caught, verifies **AC-11**
- Lexical limits, completeness direction: a decomposition covering every distinct parent content token passes; one dropping a content bearing clause fails as `incomplete`; a parent token repeated three times is satisfied by one occurrence in one sub claim (presence, not multiset); parent function words need no match; a response that splits one parent clause across two sub claims still passes, verifies **AC-11**
- Check ordering and retry: a malformed empty text row fails as `provider.decompose` before duplicate normalization could pair two empty strings; empty, over cap, and duplicate fire in their stated order ahead of the two half test; a two half failure triggers exactly one retry, and a second invalid response drops the parent, verifies **AC-6**, **AC-7**, **AC-11**
- Tie break determinism: a sub claim token eligible against two parent tokens takes the first unused one in parent order, and the same input always reaches the same verdict, verifies **AC-11**
- Semantic limits: a decomposition that preserves every content token while dropping `not`, reversing actors, or reordering relations passes the lexical test, documenting that the check makes no semantic guarantee and that entailment is the only defence, verifies **AC-11**
- Marker strip at the generation boundary: a draft sentence carrying a bracketed multi id group, one carrying a bare `ch_` id mid sentence, and one carrying a trailing group all reach `DraftSentence.text` with no chunk id and single spaced prose; `chunk_ids` is unchanged in each; a sentence whose text is only a marker fails as empty text rather than reaching output; and a sentence that was one sentence only because a marker followed its period is judged on the cleaned text, verifies **AC-13**
- Marker regex edge cases: an uppercase hash is stripped under the case insensitive rule; `ch_` followed by 63 or 65 hex characters is left alone, since it is not an id and the word boundary stops a 64 character prefix match; a comma separator with no surrounding space and one with spaces both parse inside a group; and a mixed group such as `[see ch_<64 hex>]` loses only the bare marker and keeps its brackets and its prose, verifies **AC-13**
- Whitespace repair after the strip: a trailing group before a full stop leaves no space before it, a mid sentence group leaves no space before the following comma, an existing parenthetical with no marker in it is untouched, and a sentence with no marker at all is returned unchanged. These pin the readable prose AC-4 emits verbatim, verifies **AC-4**, **AC-13**
- Duplicate collision from the strip: two draft sentences with identical prose and different markers become identical after stripping and fail the response as a duplicate, which is the intended reading rather than an accident; a deterministic test pins it so the behaviour is chosen rather than discovered, verifies **AC-13**
- Marker strip restores the cost bound: a sentence that is verbatim in its cited chunk **except** for an inline marker takes the containment shortcut after the strip and pays no decomposition call, the case that made AC-5 silently dead, verifies **AC-5**, **AC-13**
- Cost bound: a fully contained sentence skips decomposition, while a sentence with no available evidence skips all providers, verifies **AC-5**, **AC-8**
- Provider failure: malformed decomposition or coverage gets one repair, then fails with the correct provider code at `claim_verification`, verifies **AC-7**, **AC-12**
- No emitted sentences: every canonical facet receives a deterministic uncovered row and coverage is not called, verifies **AC-12**
- Multi clause coverage: a single emitted sentence stating a three part decision covers its facet, the case experiment 0002 recorded as wrongly abstaining under the fragment contract, verifies **AC-4**, **AC-12**
- Coverage row integrity: unknown, missing, duplicate, or out of order facet ids and invalid sentence ids fail validation, verifies **AC-12**
- Directness table: a stated decision covers a decision facet; a reason, premise, consequence, unrelated sentence, cross sentence combination, or anaphoric fragment does not; one compound sentence may cover several facets only when it states each answer, verifies **AC-4**, **AC-12**
- Diagnostic split: a merged query 4 facet reports `facet_extraction`; separate facets with a wrongly covered decision report `coverage_directness`; an uncovered decision with an answered result reports `query_state`, verifies **AC-2**, **AC-12**
- Abstention surface: sub claim and dropped sentence rows remain in trace, but public sentences and citations are empty, verifies **AC-4**, **AC-12**
- Directness on whole sentences: the directness table cases are re-run against emitted parent sentences rather than fragments, confirming a compound sentence covers several facets only when it states each answer, verifies **AC-4**, **AC-12**
- Self corpus gate: against the frozen fixture of this repository's own specs with this spec held out, the paired decision query answers from its source record with a whole sentence and the paired reason query keeps abstaining. The queries and their expected records live in the fixture manifest, not here, so this spec cannot become a source for its own gate's answer. The cheap gate that falsified the previous build, verifies **AC-4**, **AC-12**, **AC-14**

A difference invalidates the fixture and is reported as a finding rather than absorbed, verifies **AC-14**

## Consequences

**Positive**:
- The fused clause fabrication can no longer hide inside a sentence; query 4 and query 5 can abstain honestly.
- The verification unit now matches the attack surface, atomic claims instead of whole sentences.
- Cost is bounded: only non verbatim sentences pay the decomposition call.
- The trace shows the split itself, so a bad split is visible, and the empty, dropped, and missing signals point at upstream problems.
- Answers read as prose again. The output is the drafted sentence, so the orphaned references and exploded lists that experiment 0001 recorded cannot occur.
- A decision that takes several clauses to state can be answered. Experiment 0002 showed the fragment contract made such decisions unanswerable, since coverage may not combine sentences and no fragment stated the whole decision.
- Coverage becomes reliable in both directions from one change. A vacuous fragment can no longer cover a facet, because fragments are never emitted; and an informative sentence is no longer split into pieces that individually cover nothing.
- The lexical test has one job and one shape, so the granularity argument that consumed two build cycles cannot recur. A removed sub claim breaks completeness by construction, so per sub claim dropping is not a coherent option to relitigate.
- The additive tolerance is now safe to loosen, because a sub claim never reaches output; its only job is to stop substitution. Calibration stops being a safety question and becomes a measurement.
- The answered state again means every fixed facet has a direct answer. Grounded partial material cannot silently stand in for a missing decision.
- Missing citations can never escape the accepted context boundary into output.
- AC-5 is live again. The containment shortcut was unreachable for every marker bearing sentence, so the cost bound the spec claimed was not being paid; roughly half the sentences were paying a decomposition call the spec said they should not.
- The marker fix lands where the artifact enters the system, so every later consumer of `text` inherits it. The emitted answer also stops showing raw chunk ids to the reader, which nothing had noticed as a separate output defect.
- The self corpus gate becomes a fixture with a held constant input, so a changed gate result can be attributed to the code. Against the live tree it could not: editing any spec changes the gate's evidence, and the gate tests code and corpus content at once.

**Negative / tradeoffs**:
- The frozen fixture goes stale by design. It stops reflecting the current specs the moment a spec changes, and re baselining it is a deliberate step someone has to take. That is the cost of a held constant input, and the manifest hashes make the drift visible rather than silent.
- The fixture duplicates spec content inside the repository. It is a copy of decision records living beside the real ones, which is exactly the second source this project warns about elsewhere. It is mitigated, not eliminated, by keeping it outside `docs/specs/` (so no tool reads it as a record) and by the manifest naming its source commit.
- The marker strip is a repair on the boundary, not a guarantee about the model. If the model finds a new way to write an id, the strip's fixed shape does not cover it. The shape is pinned to what `chunk_id` produces and matched case insensitively, so this is bounded, but it is still a pattern match on model output.
- The strip makes an existing failure path reachable more often. Two draft sentences whose prose is identical and whose markers differ now collide and fail the whole response as a duplicate. The rule is unchanged and the reading is deliberate, but the rate is not: before AC-13 those sentences were distinct strings and both survived.
- The fixture is not a byte faithful stand in for the live corpus, only a chunk faithful one. Its records resolve no code paths, so their `evidence` sets are smaller and their `mentions_unresolved` counts higher than a live adaptation produces. Task 11 verifies the chunks match and the gate reads only those, so the divergence is confined rather than removed.
- One more provider call per non verbatim sentence adds latency and cost to those queries; a sentence that decomposes into K sub claims that all fail containment can add up to K further entailment calls on top.
- The decomposition model can split poorly, which can keep a fabricated fragment that separately passes verification or drop grounded content; the trace makes both visible but does not fix them.
- Under splitting is a known, unresolved risk: if the decomposition returns the whole sentence as a single sub claim, that sub claim's entailment check degrades to today's failing whole sentence check for that sentence. This feature makes the sub claim count visible in the trace so an under split is observable, it does not guarantee against it.
- **One bad clause now costs a whole sentence.** A sentence whose sub claims are all supported but one loses every grounded clause it carried, not just the offending one. This is the deliberate trade for whole sentence output, and it will raise the abstention rate.
- **The lexical tolerance now drives the abstention rate**, because an unverifiable sub claim and an unsupported one have the same effect on the parent. A harmless rephrase the stem rules do not cover drops a good sentence. Experiment 0002's `S1.4` is exactly this case, and it means the revised build does not automatically pass that query; task 13 exists to calibrate it. The difference from the earlier drafts is that mis-calibration now produces a plain abstention, which the harness measures, rather than strange output nobody can reason about.
- The lexical test cannot prove preserved actors, negation, scope, order, or relations. Entailment remains responsible for factual support.
- Completeness is measured on content tokens, so a decomposition that keeps every content word but inverts the parent's meaning (a dropped negation, a reversed relation) passes the lexical test. Entailment is the only thing standing between that and output, which is a real limit of a deterministic check.
- The 6 of 6 acceptance gate is strong evidence, not a measured abstention rate; a true rate needs more runs.
- Coverage uses the larger fixed generation model, so every nonempty query costs more than the earlier coverage call.
- Strict complete coverage can abstain even when some emitted sentences are useful. A future partial answer surface would need to say which facets remain unanswered instead of calling the result complete.

**Neutral**:
- `schema_version` stays 2; the five trace fields are additive and query results are not read back from persistence.
- No store change, no rebuild, no new configuration.
- Query 2 citation completeness remains out of scope. Fixed facet coverage cannot demand an omitted record that no facet names.

## Settled decisions

The three decisions this spec owed were settled on 2026-08-13 and are now written into the criteria above. Recorded here as a short index, with the reasoning in [rationale.md](rationale.md).

**OD-1, inline citation markers in the draft text: strip them at the generation boundary, and reword the prompt.** Now **AC-13**, with the prompt text in Provider contracts and the work in task 9. The marker is a serialization artifact and `chunk_ids` already carries the same data as a validated structured field, so the fix belongs where the artifact enters the system rather than in every rule that later trips over it. The rejected option, teaching the matcher to ignore chunk id shaped tokens, is smaller but leaves AC-5 dead, leaves raw ids in the rendered answer, and hands the same problem to every later consumer of `text`.

**OD-2, what the self corpus gate reads: a frozen fixture with this spec held out, generated by a committed script.** Now **AC-14**, with the work in task 10. Both halves of the original question are taken, for different reasons: holding this spec out fixes the contaminated instance, and scrubbing verbatim expected answers out of spec prose removes the class, since nothing checks for it and the next spec can contaminate a different gate. The fixture is frozen rather than rebuilt live because this gate measures code behaviour, which makes it a test fixture whose input should be held constant; a live build tests code and corpus content at once and can attribute a change to neither.

**OD-3, `DECOMPOSE_SYSTEM_PROMPT` is out of sync: record the shipped text as the constant.** Now in Provider contracts, verbatim. The completeness instruction `/develop` added is correct and load bearing, not a drift to revert: without it the AC-11 completeness half fires on correct behaviour, because the prompt would ask for only one of the two directions the validity test measures. This turned out to be independent of OD-1 rather than sequenced behind it, since OD-1 changes `ANSWER_SYSTEM_PROMPT` and OD-3 changes `DECOMPOSE_SYSTEM_PROMPT`.

The general form matters more and nothing currently tracks it: a split into several sub claims can still leave a fabricated clause sitting in the same sub claim as the borrowed clause that camouflages it, which reproduces the original weld failure at smaller scale. The lexical test cannot see this, because it enforces only that tokens are conserved, not that the split boundaries isolate anything. Watch the sub claim counts and the split boundaries in the live traces, and revisit with a deterministic minimum split heuristic or a hybrid clause splitter (Option 5 in rationale.md was rejected for the general case, not necessarily as a narrow fallback here).
- [ ] An entailment grounded sub claim keeps all available parent citations rather than a narrowed set, since `entail_verdict` has no per chunk attribution. If over citation appears in practice, consider extending its schema to name supporting chunks.
- [ ] Surface known corpus gaps at query time (experiment 0001 finding F4, experiment 0002 still open). `adapt` reports the records it skipped, and that signal dies there. A query answered from a knowingly incomplete corpus carries no sign of it, and experiment 0001 showed the result can be a fluent, correctly cited answer that inverts a shipped decision. Needs a decision on where the signal lives (the manifest, the store, or the query result) and whether it warns or blocks. Out of scope here because it is not a verification defect; the pipeline behaved correctly on the evidence it had.
- [ ] The adapter does not populate `supersedes`, so the supersession path that `docs/user-guide.md` documents is tested only against synthetic data. This is the second half of the same gap: even with a complete corpus, nothing marks spec 0007's scope decision as later reversed by spec 0008. Sequence this behind the corpus gap item, since both concern how the tool knows a record is stale.
